## 2. Как пользоваться стендом

```sh
cd "/Users/dimasik/Antigravity Project/claude agent/neo3-glass"
node scripts/preview-stand/stand.mjs up        # собрать клиент, поднять сервер, напечатать адреса
node scripts/preview-stand/stand.mjs status    # жив ли, на каком порту, те же адреса
node scripts/preview-stand/stand.mjs down      # остановить и убрать всё своё
node scripts/preview-stand/stand.mjs help      # все параметры
node --test scripts/preview-stand/lib.test.mjs # тесты чистых частей (в npm test не входят)
```

- `up [--port N] [--no-build] [--no-seed]`. Порт по умолчанию — первый свободный от 3917; 3001 и 3005
  не берёт никогда. Сборка клиента — `vite build` в `dist/` этой копии (около двух минут, на
  занятой машине дольше; в журнал идут только ошибки сборки).
- **Стенд уже работает → `up` второй не поднимает**: пересобирает клиент и печатает те же адреса.
  После правки `src/` — `up`, затем обновить страницу. После правки `server/` — `down` и `up`.
  Поменял только файлы рамки — `up --no-build`.
- `down` останавливает сервер, удаляет `scripts/preview-stand/runtime/` (временный `HOME`, база,
  демо-проекты, журнал) и `dist/`, если его собрал стенд.
- Сервер получает `HOME`, `USERPROFILE`, `DATABASE_PATH`, `SERVER_PORT`, `HOST=127.0.0.1` из
  `buildServerEnv` (`scripts/preview-stand/lib.mjs`) и не наследует окружение оболочки, кроме `PATH`,
  `TMPDIR` и языка. Фоновые сторожа сервера (Telegram, расписания, очередь) выключены.
- Вход: пользователь `stand` (админ), пароль случайный, вход выполняет сама ссылка рамки.
- Демо-данные: 10 проектов, 2 закреплены; в `shop-frontend` чат с перепиской (таблица, код,
  вызов инструмента, длинная строка без пробелов).

Ссылка рамки: `http://127.0.0.1:<порт>/stand/frame.html?<параметры>`

| Параметр | Значение |
|---|---|
| `w=390` | ширина экрана (390, 430; любое целое 320–1280) |
| `h=844` | высота; по умолчанию 844 для 390 и 932 для 430 |
| `theme=ember` | тема одного телефона |
| `variant=city` | вариант «Неона» (пишется в `localStorage.neonVariant`) |
| `themes=ember,glass,neon:city` | до четырёх телефонов рядом, у каждого своя тема (вариант — после двоеточия) |
| `path=/session/<id>` | путь приложения внутри рамки; ссылку «Чат с перепиской» печатают `up` и `status` |
| `path=/?panel=schedules` | открыть экран-панель сразу (в ссылке — `path=/%3Fpanel%3Dschedules`) |
| `zoom=fit` | `fit` — уместить в окно; число 0.25–3 — свой масштаб |
| `login=0` | не входить (экран входа) |
| `sync=0` | тему записать только на «устройство», не в аккаунт |
| `fresh=1` | сначала очистить `localStorage` («новое устройство») |

Страница готова, когда у `<body>` появился `data-stand-ready`; в `data-stand-problems` — число
непринятых параметров и ошибок (сами они написаны красным на странице). Четыре телефона на 390
встают в окно 1280 × 800 в масштабе 0,79; два — 0,91.

Для `browser.eval` на странице есть `window.stand`:

```js
stand.info()                                  // по телефону: innerWidth, isMobile, theme, variant, dark, path
stand.click('[data-home-menu]')               // шторка (до таска 04; после — кнопка «Проекты» нижней панели)
stand.click('[data-home-project] > button')   // открыть первый проект → пустой чат
stand.click('[data-home-settings]')           // настройки (до таска 04)
stand.clickText('Меню')                       // нажать кнопку по подписи в каждом телефоне
stand.point(selector, i)                      // координаты элемента для browser.click {x, y}
stand.each((doc, win, i) => …)                // свой замер в каждом телефоне; doc(i), win(i) — по одному
```

`stand.click` нажимает элемент программно. Кнопка проекта на «Домой» — это `button` внутри
`[data-home-project]`, не сама обёртка. Замер делай через `stand.each` и `getBoundingClientRect` /
`getComputedStyle` — он не зависит от масштаба рамки.

Чего рамка не показывает — и что с этим делать:

- **Размытие** — не рисуется в снимке вовсе. Стекло на стенде оценивается по плотности без размытия
  (так его увидят при «Уменьшить прозрачность»); само значение размытия читается через
  `getComputedStyle(el).backdropFilter`. Замер кадров с размытием в рамке недостоверен.
- **Вырез, нижняя полоса, клавиатура, режим «с домашнего экрана»** — нет: `env(safe-area-inset-*)` = 0,
  `body.pwa-mode` не ставится. Их проверяют тесты (`pwaSafeArea`, `viewportBottomGap`, `keyboard-insets`).
- Браузер представляется Safari на Маке: правила `@media (pointer: coarse)` и `(hover: none)` не
  срабатывают (`src/index.css:895`, `:911`, `EffortControl.css:21`).
- Полосы прокрутки рамка прячет сама, как на телефоне: без этого каждый прокручиваемый блок был бы
  на 17 px уже, чем на айфоне.
- Все телефоны одной страницы делят один `localStorage`. Тема каждого держится, пока его не
  перезагрузили. До таска 03 приложение при запуске перечитывает тему аккаунта, поэтому с `sync=0`
  покажет тему аккаунта, а не заданную в ссылке, — после таска 03 должно стать наоборот.

Если встроенный браузер недоступен: ссылку рамки можно открыть вручную в любом браузере на этом
Маке — вход она выполнит сама. В отчёте таска тогда написать, что глазами не проверено.

## 4. Чем темы различаются и чем нет

Различаются:

- **Фон**: `ember` — живое видео и зерно; `glass` — светлый градиент; `neonCity` — фото города под
  затемнением; `codex` — ровный графит.
- **Цвет акцента**: оранжевый, бирюзовый, голубой, почти белый.
- **Шрифт**: `ember` — Geologica; `glass` — Outfit; `neonCity` — моноширинный JetBrains Mono с
  разрядкой; `codex` — системный.
- **Скругление**: 10 / 16 / 8,8 / 10 px (`ember` и `codex` совпадают).
- **Тени**: `ember` и `codex` — нет; `glass` — мягкие; `neonCity` — едва заметные.
- **Материал панелей**: `glass` — белый 42–46 %; `ember` — тёмный 74–88 %; `neonCity` — почти
  сплошной; `codex` — сплошной.
- `codex` один перерисовывает поле ввода: скругление 18 px, круглая «отправить».

Не различаются — и поэтому «дизайн у тем практически идентичный»:

- Раскладка и размеры каждого экрана одинаковы до пикселя: шапка чата 45 px с шестью кнопками
  32 × 32, поле ввода 374 × 123, чипы 32 px, сетка «Домой» 74 × 106, шторка 332 px, строки настроек.
- Значки проектов и плитки «Меню» — одни и те же во всех темах.
- Формы кнопок одни: квадрат со скруглением 8–10 px. Плавающих кругов и пилюль, как в эталоне
  (Grok), нет ни в одной теме — всё собрано из пристыкованных полос.
- Шапка чата, настройки и панели залиты сплошным цветом: фон и материал темы на них не видны.
  На этих экранах `ember`, `neonCity` и `codex` отличаются только оттенком серого и шрифтом.
- Стекло есть только в `glass`; в остальных трёх оно либо почти сплошное, либо снято.
- Сообщения одной формы (`rounded-2xl rounded-br-md bg-muted`), ответ агента без подложки.
- Плотность и длительности почти равны (`--density` 1 против 1,05; 0,2 с против 0,26 с).
- `ember` и `codex` делят скругление и отсутствие теней: вся разница — цвет, шрифт и картинка.
