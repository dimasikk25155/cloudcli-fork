## Что должно заработать

Во вкладке «Второй чат» (и «Побочный чат» `/btw`) на холсте справа рендерится тот же `ChatInterface`,
что слева, с пропом `embedded`: та же лента с карточками и группами инструментов, тот же композер
(режим, модель, effort, контекст, кэш, лимиты, микрофон, стоп), индикатор «Думает…», вопросы с кнопками,
очередь. Два чата живут рядом и не мешают друг другу: стримы не смешиваются, «Стоп» не гаснет от чужого
чата, двойной Esc — только в своём, черновики раздельные, переключение вкладок холста ничего не сбрасывает,
выпадашки не уезжают за правый край. Левый чат работает как раньше.

Границы — `interfaces.md` п. 1–5 (форма `embedded`, `chatRuntime`, `keepMounted`, швы для тестов).
Карта мест в коде (B1–B9 и мелочи) — `notes.md`.

## Из брифа, дословно

> «второй чат должен быглядить аналогичну первому, иначе это не имеет никакосмысла, я могу рядом вторую вкладку открыть тупо, нужно чтобы если это работало так работало правильно»

## Разделы спецификации

Решение R01–R14 (с R11.1–R11.5), Решения по реализации.

## Критерии приёмки

- [ ] Вкладка `chat`/`btw` с выбранным чатом рендерит `ChatInterface` с `embedded` (не `feedRows`); старые `feedRows`/`chatSendFrame`/черновики-скролл `sideChatStore` удалены вместе с их тестами
- [ ] Два чата стримят одновременно — тексты не смешиваются (тест `createStreamBuffers`: дельты A и B, `complete` B не трогает A)
- [ ] `chat_subscribed` для сессии, на которую экземпляр не подписывался, игнорируется (тест `shouldHandleSubscribedAck`)
- [ ] Двойной Esc в правом чате не останавливает левый, Esc из холста основной игнорирует (тест `isEscapeForInstance`)
- [ ] Ключ черновика правого чата содержит sessionId, левого — прежний (тест `draftStorageKey`)
- [ ] Embedded-экземпляр не слушает `COMPOSER_DRAFT_EVENT`/`WORKSPACE_CHAT_EVENT`, не играет звуки, не ставит `[Done]`, не пишет `selected-provider`, не рендерит QuickSettingsPanel/SessionHubBar/ProviderSelectionEmptyState, не держит второй watchdog, не показывает кросс-движковые модели и «Новый чат»
- [ ] Переходы правого чата (`handleSessionEstablished`, эстафета, треды) → `embedded.onRetarget`, маршрут не меняется; `/btw`, `/advisor` из правого открывают вкладку на `embedded.hostSessionId`
- [ ] Свежий `/btw`, которого нет в `project.sessions`, открывается: `paneSession` собирает сессию из id/провайдера/проекта (тест); первая отправка не создаёт новый чат
- [ ] `processingSessions` и колбэки доходят до вкладки через `chatRuntime` (оба монтажа `WorkbenchCanvas`): индикатор «Думает…» и «Стоп» справа видны во время хода
- [ ] Вкладки `chat`/`btw` — `keepMounted: true`: после переключения на другую вкладку холста и обратно прокрутка и черновик на месте
- [ ] Видимый правый чат, закончивший ход, помечается просмотренным (`attentionStore.markSeen`)
- [ ] Выпадашки композера прижаты к окну (тест `clampMenuLeft`)
- [ ] Сбой рендера правого чата — «Чат не открылся» + «Открыть чат целиком», страница жива
- [ ] `npm run typecheck`, полный `npm test` (канонический TMPDIR) и изолированная `vite build --outDir "$(mktemp -d …)"` зелёные; `npm run build` НЕ запускать
- [ ] Вживую: локальный vite-превью этого worktree против боевого API (как в прошлых сборках) — скрин левого и правого чата рядом, одинаковый вид ленты и композера; скрины в `.autopilot/2026-11-05-neo3-second-chat--wip/evidence/`
