# Разведка Neo3 под «Grok Bot»-апгрейд (05.11, по коду worktree `neo3-grokbot`, ветка `feat/neo3-grokbot`)

Пути от корня worktree. Проверено чтением кода, не только CLAUDE.md.

## 0. Главное: что уже есть, чтобы не строить второе
| Хотим из Grok Bot | В Neo3 уже | Где |
|---|---|---|
| Routines по расписанию | ДА, но только «в такое-то время/дни недели» через ОС (launchd/systemd) | `server/modules/schedules/`, UI `src/components/schedules/SchedulesPanel.tsx`, пункт меню «Расписания» |
| Routines по событию | НЕТ (нет триггеров webhook/файл/пуш) | — |
| Цепочка шагов | ДА («Сценарии»: список промптов по проектам, вывод шага идёт дальше) | `server/modules/pipelines/` |
| Именованный бот с ролью/памятью | НЕТ сущности. Есть только `workMode` (инструкция в system prompt) и `.claude/agents` самого Claude CLI | см. §4 |
| Команда ботов (штаб -> помощники -> сводка) | ДА, в виде тредов: `spawn_thread`, `thread_status`, «Треды готовы» | `server/modules/threads/` |
| Skills | ДА (список/установка по провайдеру) | `server/modules/providers/services/skills.service.ts`, UI `src/components/skills/` |
| Коннекторы/MCP | ДА (CRUD по провайдеру + global) | `server/modules/providers/services/mcp.service.ts`, UI `src/components/mcp/` |
| Auto-review rules | ЧАСТИЧНО: «Разрешить и запомнить» (`allowedTools`/`disallowedTools`), `permissionMode`; правил «одобрять автоматически по условию» нет | §6 |
| Облачный компьютер с браузером | ЧАСТИЧНО: Safari вживую (только Mac, админ), `browser-use` (свой браузерный MCP на Mac) | `server/modules/safari-live/`, `server/modules/browser-use/`; VPS-агент «Крабик» |
| Secure secret request | ЧАСТИЧНО: страж ключей + `POST /api/secrets/stash` (перенос вставленного ключа в файл секретов); запроса «агент просит ключ -> человек вводит в защищённое окно» нет | `server/modules/secrets-stash/`, `shared/secret-detect.ts` |
| Пуш + Telegram человеку | ДА, готовые каналы | §7 |
| Аудит/траты фоновых прогонов | ДА | `server/modules/governance/` (`recordAuditEvent`, actor'ы) |
| Рабочее пространство (задачи, документы, письма, поручения) | ДА | `server/modules/agent-workspace/` + `managed-documents`, `agent-mail`, `workspace-team` |

Ключевой вывод: общий планировщик ЕСТЬ (`schedules`, но только cron-подобный «час:минута + дни недели», через ОС, без событий и без «агента с ролью»). Сущности «агент/бот с ролью и памятью» НЕТ. Новый модуль «боты» должен ложиться НА `schedules` + `runHeadlessPrompt` + `threads`, а не рядом.

## 2. Запуск агента без человека (три разных входа)
1. `runHeadlessPrompt(options)` — `server/modules/agent-run/agent-run.service.js` (реэкспорт `agent-run/index.js`). Параметры: `{projectPath, prompt, userId, provider?, model?, effort?, sessionId?, onEvent?, actor?, readOnly?}`; возвращает `{sessionId, text, messages}`. Движок: `resolveRunEngine` = явный provider -> `providerPreferencesDb.defaultProvider` -> `DEFAULT_UNATTENDED_PROVIDER='grok'`. `checkProjectAccess(userId, path)` внутри (проект зарегистрирован, у не-админа есть доступ). Права: всегда `permissionMode:'bypassPermissions'` (без одобрений!). `readOnly:true` — только Claude (инструменты чтения без Bash/MCP) и Codex (снимок без инструментов); Grok и прочие -> ошибка. `actor` из `KNOWN_ACTORS` = `user|schedule|pipeline|telegram|api|git-helper|duet|system`: НОВЫЙ актор (напр. `bot`/`routine`) надо добавить в этот Set, иначе в аудите станет `system` + warning. Аудит: `recordAuditEvent` (`run.start/finish/error`), расход `RunMeter` — `server/modules/governance/`. Не-админам — песочница (`userJailFor`). Сессия в таблицу `sessions` как app-чат НЕ заводится (нет `createAppSession`): результат живёт как provider-сессия, в сайдбар попадает через синхронизатор; для «чата бота, который видно в списке» нужен путь №2/№3.
2. «Как тред» — `threadsService` (`server/modules/threads/threads.service.ts`, `openThread`): `sessionsService.createAppSession(provider, projectPath)` -> `linkSession({childSessionId, parentSessionId, relation:'thread', user})` -> `sessionsDb.updateSessionCustomName` -> `sessionThreadsDb.insert` -> `startRun({...})` -> `broadcastUpsert`. Запуск — через `ThreadRunControl.start({sessionId,userId,parentSessionId,content,options})`, который сервер ставит в `server/index.js:214` `threadsService.setRunControl(createThreadRunControl(chatDependencies))`. Тот же контроль у мастер-сессии (:223) и авто-переноса (`createAutoRelayRunControl`).
3. `beginChatSend(ws, userId, userRole, data, deps, access)` — `server/modules/websocket/services/chat-websocket.service.ts:275` (НЕ экспортируется; наружу — `createThreadRunControl` :843, `createAutoRelayRunControl` :876, плюс ветка `idea` ~829). `access: ChatSendAccess` (:209): `{kind:'socket'} | {kind:'verified-answer'} | {kind:'idea',userId} | {kind:'thread',userId,parentSessionId} | {kind:'auto-relay',userId,parentSessionId,...}`. Проверка доступа — цепочка тернарников ~стр. 300; для нового вида (`'routine'`/`'bot'`) нужно: новый вариант в типе, ветка в `accessDenied`, свой `createXRunControl(dependencies)` по образцу `createThreadRunControl`. Дальше: `chatRunRegistry.startRun` (даёт статус working/waiting/done в «Ждут тебя», индикатор, Стоп), `userJailFor`, токен треда (`threadTokens.issue` -> `withThreadsEnv`, env `NEO3_THREADS_TOKEN`). Опции модели/effort/permissionMode идут в `data.options` (`model`, `effort`, `permissionMode`, `projectPath`, `usageGuardOverride`).
- Новый чат: `POST /api/providers/sessions` (`server/modules/providers/provider.routes.ts:~650`) `{provider, projectPath, parentSessionId?, relation?}` -> `sessionsService.createAppSession` (`services/sessions.service.ts:125`); для ребёнка — `assertCanLinkNewChild` ДО создания, `linkSession` после, при отказе строка удаляется. `autoRelayService.applyNewChatDefaults` вызывается там же.
- Провайдер/модель/effort: список разрешённых — `src/utils/providerSelectionPolicy.ts` (клиент: Claude `opus[1m]`,`sonnet[1m]`,`fable`; Codex Astra/Sol; Grok `grok-4.7`,`grok-4.7-build-fast`), `resolveChatSelection` в `providerModelState.ts`; сервер — каталог `providerModelsService.getProviderModels(provider)` (`.models.DEFAULT`), для тредов `DEFAULT_THREAD_MODELS`, `DEFAULT_THREAD_PROVIDER='grok'`, `LOCAL_THREAD_MODELS=['local-qwen35-9b','local-ornith-9b']`, `isAllowedModel`. Предпочтения пользователя: `providerPreferencesDb.getProviderPreferences(userId)` (`defaultProvider`, `models`, `efforts`, `workMode`).

## 3. Расписания: что есть
- Общий планировщик ПОЛЬЗОВАТЕЛЬСКИХ задач ЕСТЬ, но через ОС: `server/modules/schedules/`. Таблица `schedules` (`id,user_id,name,kind('prompt'|'pipeline'),project_path,prompt,pipeline_id,hour,minute,weekdays('' = каждый день, '0..6'),enabled,os_label,last_run_at,last_status`), репозиторий `server/modules/database/repositories/schedules.db.ts` (`schedulesDb`). `schedule-host.ts`: `ScheduleHost.create/remove/list` -> launchd plist (`ru.neo3.neo3-schedule-<id>` в `~/Library/LaunchAgents`) на Mac / systemd user timer на Linux; `NEO3_SCHEDULE_DIR` уводит тесты от настоящих LaunchAgents. Запуск: launchd -> `node schedule-runner.js <id>` (`schedule-runner.js`) -> `runScheduleNow(id)` -> `runHeadlessPrompt({actor:'schedule', ...})` ИЛИ `pipelinesService` (kind `pipeline`, `last_status` = «запущен»). Сервер может быть выключен — раннер сам читает SQLite. API: `/api/schedules` (`schedules.routes.ts`: list/create/put/patch(enabled)/run-now/delete), `authenticateToken`, доступ к проекту проверяется `checkProjectAccess` по владельцу. Мода у расписаний НЕТ (доступны всем).
- Ограничения: нет интервалов («каждые N минут»), нет событий, нет модели/провайдера/effort в строке (берутся из предпочтений пользователя), нет результата-в-чат/уведомления по итогу (текст идёт в лог launchd; пуша «расписание отработало» нет), нет настроек одобрения. Всё, что нужно Routines, расширяется здесь (колонки через `addColumnToTableIfNotExists`).
- Ночные задачи сторонние: `server/modules/nightshift/` — только ЧТЕНИЕ plist `~/Library/LaunchAgents` и `~/.claude/night-shift/runs` (навык night-shift), UI `src/components/nightshift/NightshiftModal.tsx` («Задачи»). Планирует не Neo3.
- Внутрисерверные таймеры (`setInterval`, не планировщик, а сторожа): дуэт `duet.runtime.ts` (тик 60 с, первый через 30 с; бриф 08:30 МСК и ночное окно 23-08 считаются внутри `duet.service.ts` по `MSK_OFFSET_MS`), крабик `krabik-watch.service.ts` (`CHECK_INTERVAL_MS`=20 с), память `memory-suggestions.service.ts:383` (10 мин, первый через 2), `vps-alerts.service.ts`, `keep-awake` (`TICK_MS`), `telegram.service.ts` (typing). Upstream-проверка — отдельный launchd (`scripts/com.dimasik.neo3-upstream-check.plist`, 09:15), не в процессе сервера.
- Общего внутрисерверного cron/очереди нет: каждый сторож — своя `setInterval` + флаг `busy` + `NEO3_*_WATCH=off`. Для интервальных/событийных рутин придётся либо писать единый тик (по образцу duet.runtime), либо оставить launchd только для «время суток».

## 5. Команды агентов (треды)
- `server/modules/threads/`: `threads.service.ts` (`createThreadsService(deps)`, синглтон `threadsService`), `thread-tokens.ts` (токен на прогон, в БД хэш, живёт до конца прогона + 24 ч), `threads.routes.ts` (`/api/threads/tools/:name`, Bearer = токен, loopback only, иначе 403 `NOT_LOCAL`), `threads-mcp-registration.ts` (регистрация stdio-MCP `neo3-threads` в `~/.claude.json` и `~/.codex/config.toml`, только при `NEO3_THREADS_MCP=on`), stdio-MCP `server/threads-mcp.ts` (`cli.js threads-mcp`). Таблицы `thread_tokens`, `session_threads(thread_session_id PK,parent_session_id,user_id,provider,model,permission_mode,created_at,started_at,seen_at,notified_at)`; связь — `sessions.parent_session_id`+`relation='thread'` (`server/modules/session-links/`, `shared/session-links.ts`).
- Инструменты (описания в `threads-mcp.ts`, `tools[]`): `spawn_thread{prompt,title?,provider?(grok|claude|codex|local),model?}`, `thread_status{threadId?,wait<=600}`, `message_thread{threadId,text}` (отказ, пока тред занят), `stop_thread{threadId}`, плюс `workspace_action` (документы/поручения/почта/артефакты/группы/`settings.propose`/`safari.show`; реализация `agent-workspace/tools.ts` `createWorkspaceTools(...).call`).
- Лимиты: `MAX_WORKING_THREADS=3` (счёт working + «открываются сейчас» через `openingByParent`, синхронно -> параллельные вызовы не обходят; код `THREAD_LIMIT` 429), `NESTED_THREAD` (тред не открывает треды, 403), `MAX_THREAD_WAIT_SEC=600`, `CLAUDE_LIMIT` 429 для Claude-тредов при почти исчерпанном 5-ч лимите (локальные модели без стража), модель/провайдер проверяет `isAllowedModel`. Тред = обычный чат того же проекта и пользователя родителя; права `permission_mode` наследуются от токена родителя. У тиммейтов в Grok тредов нет.
- Да, родитель раздаёт несколько задач и получает итог: `spawn_thread` N раз (до 3 одновременно) -> «Треды готовы». Доставка итога: `sessionAttention.onChange` (`server/index.js:1612`) -> `threadsService.handleAttentionChange(sessionId)` -> `notifyParentIfReady(parent)`: если родитель не занят (`parentIsBusy`: идёт прогон ИЛИ `attention.state==='waiting'`), все его треды не `working`, есть непрочитанные (`seen_at`/`notified_at` пусты) — собирает ОДНО сообщение «Треды готовы:\n1. «title» (provider · model) — готово: <последний ответ, clip SUMMARY_REPLY_MAX> / ошибка / ждёт ответа ...» (`describeForParent`) и стартует им ход родителя через `startRun` (синхронно; не стартовало -> ждёт конца текущего хода). `thread_status` с `wait` — блокирующий сбор; прочитанное через status помечается `seen_at`. Клиент: полоса `src/components/threads/ThreadsBar.tsx`.
- «Штаб -> помощники -> сводка» для Grok-Bot-команды = родитель-чат с ролью «штаб» + треды-помощники; не хватает: имён/ролей помощников (каждый тред получает только `prompt`, роль можно вложить в prompt), >3 параллельных, вложенности (запрещена намеренно), доступа не-админ-ботов.
- Заметка: мод `modThreads`; выкл -> `NEO3_THREADS_OFF=1` в env прогона, `spawn_thread/message_thread` -> `MOD_OFF`.

## 6. Одобрение действий
- Режимы: `permissionMode` (`default`, `acceptEdits`, `plan`, `bypassPermissions`, спец. `AUTO_PLAN_MODE` в `claude-sdk.js` ~105: `autoPlanApproves` — в auto-plan все запросы кроме `AskUserQuestion` одобряются). Клиент хранит режим на чат (`chatStorage.ts`), в прогон идёт `options.permissionMode`.
- `canUseTool` — `server/claude-sdk.js:1019`: `TOOLS_REQUIRING_INTERACTION = {AskUserQuestion, ExitPlanMode}` всегда к человеку; при `bypassPermissions` пропуск; иначе сверка с `sdkOptions.disallowedTools` / `allowedTools` (`matchesToolPermission`, тест `server/tool-permissions.test.js`); иначе открытый запрос в UI. «Разрешить и запомнить» (`decision.rememberEntry`, ~1097) добавляет правило в `allowedTools` — правила живут в настройках провайдера (`settings.allowedTools/disallowedTools`, UI `src/components/settings/view/tabs/agents-settings/.../PermissionsContent.tsx`, билдер правила `buildClaudeToolPermissionEntry` в `chatPermissions.ts`). Это и есть единственный аналог auto-review: статические allow/deny по инструменту/префиксу команды. Условных правил (по пути, сумме, времени), «ревью моделью» и журнала решений нет.
- Фоновые прогоны (`runHeadlessPrompt`) вообще без одобрений — `bypassPermissions` (кроме `readOnly`, где `canUseTool` режет всё не из списка чтения). Тред наследует `permissionMode` родителя.
- Ждущие вопросы: `server/modules/session-attention/` (статусы `working|waiting|done|failed`, таблицы `session_attention`, `session_attention_seen`, `GET /api/attention`), `server/modules/pending-answers/` (`pendingAnswers.answer({...})`, `issueTokens/redeemToken`, одноразовые 24 ч, `answer_tokens`; доставка: UI/пуш/Telegram; движок `createPermissionAnswerEngine` в `server/modules/websocket/`; `AnswerDecision {allow, answers, message, updatedInput, rememberEntry}`). Здесь удобная точка для «авто-ответа по правилу»: `pendingAnswers` уже решает по запросу; правило-автоответчик можно повесить как ещё один «канал» `AnswerVia`. Мастер-сессия: `server/modules/master-session/` (все ждущие вопросы, черновики ответов моделью в `readOnly`, отправка пачкой после показа адресатов).
- Эталон безопасности для фона: `readOnly` в `runHeadlessPrompt` (брифы дуэта). `agent-blast-radius`-логика — права тиммейтов не расширять (`user-jail.ts`, `NEO3_USER_JAIL`).
