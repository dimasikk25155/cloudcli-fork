## Что должно заработать

Сервер разбирает очередь пунктов исполнителями-агентами: до 3 параллельно на очередь и до 3 очередей одновременно. Каждое задание = блок роли агента + шаблон с `{{item}}` + требование закончить строкой `ВЕРДИКТ`. FAIL переделывается с причиной прошлой попытки до лимита попыток, потом уходит в «брак». Есть «Ещё проход» по браку, ручная отметка OK, пауза, продолжение и стоп. После рестарта очередь продолжается с места. В конце Диме приходят пуш и Telegram «N OK, M брак». Расписания получают агента и флажок «Прислать итог»: прогон идёт от имени агента, итог (до 600 знаков или ошибка) досылается пушем и в Telegram, даже если раннер отработал при выключенном сервере.

## Критерии приёмки

- [ ] `createAgentQueueService.create` проверяет вход (≤500 пунктов, 1–2000 знаков, parallel 1–3, attempts 1–4, агент существует; пустой список → «нет пунктов»; шаблон без `{{item}}` → пункт в конце) — тесты
- [ ] `tick()` берёт ≤parallel пунктов на очередь и ≤3 очереди всего; исполнитель — `runHeadlessPrompt({actor:'queue', …})` через deps; вердикт OK → ok, FAIL/нет вердикта → повтор с причиной в задании, после лимита → rejected с последней причиной и выдержкой — тесты на фейковом исполнителе
- [ ] Сбой движка = FAIL попытки с текстом ошибки, очередь продолжает; для Claude-агента при запрете стража пункт не берётся (ждёт) — тесты
- [ ] `recoverOnBoot` возвращает running → pending; pause/resume/stop/retryRejected/markOk работают — тесты
- [ ] Конец очереди → одно уведомление `queue.done` («N OK, M брак», переход `/?panel=queue`), повторно не шлётся; мод `modAgentQueue` выкл → новые пункты не берутся, running-очереди → paused, уведомлений нет — тесты
- [ ] Роуты `/api/agent-queue` (admin, MOD_OFF) по `interfaces.md` §4 — тесты; сторож запускается в `server.listen` (выкл `NEO3_AGENT_QUEUE_WATCH=off`) и останавливается при выходе
- [ ] Расписание с `agent_id` идёт с ролью/движком/моделью/папкой агента; удалённый агент → статус «агент удалён» без прогона; `last_result` пишется — тесты
- [ ] `notify=1`: сторож сервера досылает `schedule.result` один раз на прогон (`last_run_at > notified_at`), ошибка тоже приходит — тест
- [ ] `SchedulesPanel.tsx`: поле «Агент» (при `modAgents`) и «Прислать итог», показ `last_result`
- [ ] `npm run typecheck` и `npm test` зелёные
- [ ] Боевое не тронуто: ни `npm run build`, ни рестарта, ни правок `~/.claude*`, `~/.codex`, LaunchAgents; тесты второго чата, Safari вживую, новой вкладки и рабочего стола зелёные
