## Возможности Grok Bot

| Возможность | Что даёт | Ограничения |
|---|---|---|
| Облачный компьютер: Linux-VM с браузером, файлами и терминалом | Бот работает при закрытом ноутбуке. В браузере сам проходит сайты без API («80% интернета без API») | Одна VM на **весь аккаунт**: общие `/workspace`, куки и логины у всех ботов. IP датацентра: маркетплейсы и банки детектят, Avito сразу даёт капчу. Прокси в браузер VM подать нельзя (проверено 23–24.08) |
| До 50 именованных ботов (имя, роль, цвет) | Отдельный «сотрудник» на тему: Художник, Критик, Статистик | Боты не граница безопасности. У каждого свой «экран», но на экран — одна задача computer-use за раз |
| Групповые чаты ботов (2–6), обмен между ботами | Штаб раздаёт поручения помощникам и сводит ответы; в UI видно «6 сообщений с 5 ботов» | Свободная болтовня ботов жжёт лимит. Больше 4–5 параллельно — дубли и шум. Штаб не видит чужие чаты и чужую память напрямую (`sport-bet/research/grok-team/verification-v2.md`) |
| Бот сам создаёт ботов | Штаб Sport-Bet создал 5 помощников, Fluid в крипто-команде — 9 | Системные инструкции созданных ботов менять нельзя, только имя и описание. Правила живут в «рабочей памяти» (подтверждено словами ботов) |
| Память (UpdateMemory, общие правила) | Роль и правила V2/V3 переживают сессии; бот пересказывает их без подсказки | Это не дообучение. Независимо проверить память нельзя — только ответом бота |
| Routines: до 50 на бота, по расписанию или по событию (Slack, GitHub, MS Teams) | Регулярная работа без человека: почтальон, бриф, ежедневный пост | Хранятся 20 последних прогонов. Событийные молча не срабатывают при зелёном «Connected». Ломаются при редизайне сайта |
| Skills: обучение показом (запись до 10 мин работы в браузере → черновик навыка) | Учить показом, а не промптом | В проектах Димы ни разу не использовались (следов нет) |
| Плагины Cursor Marketplace (Gmail, Notion, Slack, Zoom…, ~219 листингов) | Готовые коннекторы | Zoom сломан (error 4700). `grok.com/connectors` (31 шт.) — другая поверхность, не Grok Bot |
| Remote MCP | Единственный программный канал Bot ↔ наша инфраструктура: сделан `mcp.neo3.ru` (vault-mcp) | Только публичный HTTPS, localhost и приватные IP запрещены. Токен хранится у Cursor и доступен всем ботам |
| Secure secret request | Секрет маскируется, не попадает в транскрипт и в модель | Один секрет видят все боты аккаунта |
| Auto-review rules + «Execution on Local Computer» | Правила самопроверки и запрос разрешения перед действием на маке | Поле правила — 150 символов, одно английское правило за раз (Дима вставил таблицу → «rule is too long»). Режимы: Always / **Ask every time** / Never; «Allow with review» нет |
| Инструменты генерации внутри бота (картинка, правка с референсом, image→video) | **Свой пул квоты**, отдельный от веб-Imagine и Grok Build CLI. Бот смотрит свой результат и переделывает | Генератор отдаёт только 1280×720; видео 6 с, до 816×1104. Картинки падают в общую `grok.com/library` |
| Вложения и выгрузка файлов (zip, скрипты, mp4) | Бот присылает архив/скрипт/видео, их можно скачать и проверить локально (Sport-Bet V3 — zip из 16 файлов) | Большое вложение (3,6 МБ) бот читает только постранично, в `/workspace` не кладёт. SHA в облаке не проверить |
| Бета-маршрутизация трафика через свой компьютер | Домашний IP для соцсетей | Только при живом маке. Бот обязан сам проверять свой IP |
| Клиенты macOS / Windows / iPhone + веб | Тэйк-овер с телефона: один логин виден всем ботам | Linux-клиента нет. Android и iPad — нет (по августу) |
| Квота: шаги агента + токены, недельный сброс | Входит в SuperGrok Plus ($100) | Размер не публикуется, метеринг врёт (0% vs 48%). Кап на расходы **отсутствует**: on-demand без потолка, включать нельзя |
| **НЕТ:** API, CLI, вебхуков, headless, audit log, dry-run, выбора модели | — | Управление только руками или эмуляцией браузера. Тестовый прогон делает реальные действия. Привязка SuperGrok → Cursor необратима |

## Что делали руками вокруг него

### A. Скрипты через браузер для бота «Художник» (`grok-imagine-web/`)

Бот управлялся из общего агентского Edge по CDP (`127.0.0.1:19224`, `neo3-edge`). API у продукта нет, поэтому скрипты подцепляют **внутренний клиент страницы grok.com**: через `TURBOPACK.push` достают модуль `919432` → `botRelayClient`. Его методы: `usage()`, `transcriptTail({agentId,limit})`, `roster()` (статус бота idle/busy), `readAttachmentImage`, `readAttachmentChunk`. Это хрупко: номер модуля меняется со сборкой сайта.

**`bot_gen.mjs <донор.jpg> <промпт.txt> <out.jpg>`** — одна правка фото:
1. Берёт id вкладки из `.bot-target` (`.bot-target-2/-3` — для 2-го и 3-го бота); id бота — `BOT_AGENT`.
2. Если вкладка не на странице бота — переходит на `grok.com/bot/<id>`.
3. `b.usage()` → если `hasAvailableUsage=false`, выходит с кодом 3 («LIMIT»).
4. Поворачивает донора на 90° (`sips`): генератор бота отдаёт только 1280×720, так получается вертикальный кадр.
5. Собирает длинное сообщение: «прочитай все строки этикетки → выпиши, какими они станут → дай генератору короткое описание → **сам проверь результат построчно, до 4 попыток** → скопируй файл в `/workspace/` и пришли вложением → закончи строкой `ВЕРДИКТ: OK/FAIL`» + ТЗ из `prompt.mjs`.
6. Чистит композер: удаляет зависшие вложения («Удалить это вложение»), Cmd+A, Backspace.
7. Загружает файл через `DOM.setFileInputFiles`, до 12 раз жмёт «Повтори загрузку», если она зависла.
8. Вставляет текст (`Input.insertText`), Enter; если текст остался — жмёт submit.
9. Каждые 8 с читает `transcriptTail`, ждёт сообщение с «ВЕРДИКТ:» **и** статус бота idle (картинка может прийти отдельным сообщением). Таймаут 15 мин. Если бот пишет «лимит исчерпан» — код 3.
10. Берёт картинку только из `/attachments/` (ссылки `/assets/` недоступны) → `readAttachmentImage` → base64 → файл.
11. При FAIL — ошибка. При OK — поворачивает обратно, режет до 3:4, масштабирует до 1200×1600.
12. **Своя проверка поверх бота:** `label_orient.py` (tesseract) — повёрнутая этикетка → `.rotated.jpg` и FAIL.

**`bot_scene.mjs <сцена> <реф1,реф2> <промпт> <out>`** — то же, но несколько вложений (сцена + референсы), свободное ТЗ, до 3 попыток. Транскрипт сохраняется в `<out>.bot.txt`.

**`bot_fetch.mjs <tab> <agent> <path> <out>`** — скачивает любое вложение (mp4) кусками по 512 КБ через `readAttachmentChunk`.

**`batch.mjs <workdir> [worker] [workers]`** — читает `plan.json`, пишет промпты, пропускает готовое (можно продолжить с места), 2 попытки на строку. `GEN=bot_gen.mjs` переключает с Imagine на бота. При LIMIT — код 3.

**`bot_queue.sh <job>...`** — по каждой работе 2 прохода `batch.mjs` через бота. На лимите бота — стоп. Пишет в лог «готово N / всего».

**`queue.sh` / `resume.sh` / `tab.sh`** — для веб-Imagine: 3 параллельных вкладки-воркера (`.target-0..2`); при лимите ждать 30 мин и повторять.

**`bots-probe/`** (`send.mjs`, `up.mjs`, `dl.mjs`, `ev.mjs`) — первые пробы 15.10: отправить текст, загрузить файл + текст + скриншот перед отправкой, скачать вложение, перейти/выполнить JS/кликнуть/скриншот.

**QA руками:** `qa_bot.py` собирает листы-контакты (`qa/full-NN.jpg` — карточки целиком, `qa/text-NN.jpg` — крупно этикетки с ожидаемым текстом). Человек/агент просматривает **каждый лист** и переносит брак в `rejected/`. Потом снова `bot_queue.sh`.

**Что оставалось ручным:**
- Создать ботов «Художник» и вписать их id и id вкладок в файлы.
- Делить работу между 3 ботами (руками решали, какой бот какую модель шин берёт).
- Следить за лимитом и ждать сброса.
- Смотреть QA-листы и перекладывать брак.
- Переписывать промпт после брака (CDEK на этикетке, «раздутые» шины).
- Перезапускать подвисших ботов (`bot2 restart`).

## Самые ценные паттерны (по пользе в проектах Димы)

1. **Параллельные именованные работники с собственным лимитом + очередь с продолжением.** Три «Художника» по одной очереди `plan.json`, пропуск готового, код «лимит» → пауза/стоп. Pirelli: ~2 ч вместо ~4. Плюс бот — **запасной пул**, когда кончились Imagine и CLI (фургон СДЭК, карточка 245/40). *Где: Tyres (Pirelli, Ikon, Landspider).*
2. **Самопроверка с машинным вердиктом + своя страховочная проверка.** Бот сам читает результат, переделывает до N раз и пишет `ВЕРДИКТ: OK/FAIL`; скрипт принимает только OK и добавляет свою проверку (OCR поворота), брак — в `rejected/` и на 2-й проход. В Sport-Bet то же: `СТАТУС: ГОТОВО/ЧАСТИЧНО/БЛОКЕР` + независимый локальный пересчёт. *Где: Tyres, Sport-Bet.*
3. **Штаб-команда: координатор создаёт помощников, раздаёт роли, сводит ответы, держит разногласия; критик работает независимо.** Дало сверенные расчёты (330 дат совпали), 12/12 синтетических кейсов, найденные дефекты. *Где: Sport-Bet (6 ботов), Consigliere (10 ботов), аудит «десяти банков».*
4. **Роль + знания как пакет файлов + память правил с версиями (V2, V3).** Локально готовится пакет (контекст, ROLE.md, задания, критерии), бот хранит правила и пересказывает версию. *Где: Sport-Bet, Consigliere, ТЗ Samruk и Приставов.*
5. **Отметка «проверено нами / заявлено ботом» и выгрузка артефактов бота.** Скачать zip/скрипты/mp4, запустить у себя, записать хеши. Без этого бот уверенно выдавал неверное («9 Unknown», «распаковка идёт», веса «подобраны»). *Где: Sport-Bet V3, Consigliere, видео Landspider.*
6. **Мост памяти и почты через MCP (vault-mcp).** Работающая инфраструктура, но польза не подтверждена: в почтовом ящике на маке 56 брифов, ни один не прочитан. Вывод: внешний агент, который сам «приходит за почтой», ненадёжен — в Neo3 нужен пуш, а не вытяжка. *Где: Consigliere, vault-mcp.*
7. **Расписание (Routines) для регулярной работы** — бриф, ежедневный пост, мониторинг. В проектах Димы до результата **не дошло ни разу**: Samruk упёрся в IG/токен (и, вероятно, нагенерил фейков в библиотеку), бриф не забирается, крипто-мониторинг не создан. Спрос есть, надёжного исполнения не было. *Где: Consigliere, Samruk, Приставы.*
8. **Лестница доверия и границы**: задача руками → навык → расписание. Аппрув человека перед деньгами и письмами, кап на расходы, аудит-лог. У Grok Bot этого нет — в Neo3 сделан только аудит-лог. *Где: разбор 24.08, `neo3-audit-i-dengi-2026-08-24.md`.*

**Кандидаты на встраивание в Neo3 (вывод из ручной работы):**
- Очередь пачки с воркерами и продолжением с места + «ждать сброса лимита».
- Обязательный машинный вердикт в конце прогона + хук своей проверки + папка брака и второй проход.
- Команда «штаб → помощники» поверх уже существующих тредов (`spawn_thread`, лимит 3).
- Пакет роли и знаний на бота/тред.
- Пометка «проверено / заявлено агентом».
- Надёжные расписания с пушем результата (Telegram/пуш Neo3), а не вытяжкой.
- Кап на расходы и аппрув трат.
- Изоляция работников: отдельные вкладки и окна, без общей мыши.
