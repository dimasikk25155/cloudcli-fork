# Спецификация: возможности Grok Bot — в Neo3

## Задача

Дима купил SuperGrok Plus ради Grok Bot (x.ai/bot) и гонял его в нескольких проектах: три бота-«Художника» параллельно перерисовывали карточки шин, «Штаб» с пятью помощниками разбирал ставки и криптоканалы. Пользы было много, но всё держалось на руках и хрупких скриптах. У Grok Bot нет API. Ботов создавали и делили работу вручную. Брак пересылали руками. Окно Safari терялось, и приёмка зависала. Дима хочет, чтобы то, что работало у Grok Bot, умел сам Neo3 — на его подписках, на всех трёх движках, без кликов по чужому сайту.

«Наш cli» = Neo3 (cloudcli-fork): веб-оболочка, в которой Дима запускает Claude Code, Codex и Grok CLI (ASSUMPTION — принято за пользователя). «Grok bot» = Grok Bot от xAI (x.ai/bot), а не TG-бот @neo3_grok_bot и не CLI Grok Build — последний уже движок Neo3.

**Откуда блоки апгрейда** (разбор — `research-grokbot.md` рядом со спекой: вольт Obsidian, `grok-imagine-web/`, `sport-bet/research/grok-team/`, `consigliere/docs/grok-crypto-migration-2026-11-01/`):

| Что дало пользу в проектах | Где | Блок в Neo3 |
|---|---|---|
| Несколько ботов параллельно + очередь, которую продолжают с места | Tyres: 3 «Художника», Pirelli 60–70 карточек за 1,5–2 ч вместо 4; очередь Ikon ~295 карточек | Конвейер |
| Бот сам проверяет результат («ВЕРДИКТ: OK/FAIL», до 4 переделок), брак → второй проход; Auto-review rules | Tyres (этикетки), Landspider (бот сам ставит FAIL) | Конвейер + правила самопроверки агента |
| Штаб сам раздаёт роли помощникам и сводит ответы | Sport-Bet (6 ботов, 330 дат совпали с нашим пересчётом), Consigliere (10 крипто-ботов) | Штаб-команда |
| Роль + знания пакетом файлов + правила в памяти с версиями (V2, V3) | Sport-Bet, Consigliere, ТЗ Samruk и Приставов | Агенты (роль, файлы, память) |
| Routines (бриф, ежедневный пост, мониторинг) — спрос был, до результата не дошло: результат ждал, пока бот «заберёт» | бриф Consigliere (56 непрочитанных), Samruk | Рутины: агент в расписании + итог Диме сам |
| Secure secret request | Samruk (page-токен вытаскивали руками) | Запрос ключа |

## Решение

В Neo3 появятся:

1. **Агенты** — именованные «сотрудники» с ролью, правилами самопроверки, движком/моделью, рабочей папкой, файлами-знаниями и памятью правил с версиями. С агентом можно начать чат, а штаб может звать агентов помощниками.
2. **Штаб-команда** — чат-штаб открывает треды-помощников **по имени агента**: у каждого его роль, движок и модель. Штаб видит список агентов и сводит их ответы. Неделимая очередь «Треды готовы» уже есть, её не трогаем.
3. **Конвейер** — очередь пунктов (карточки, файлы, задания), которую разбирают 1–3 исполнителя-агента параллельно. Каждый ответ заканчивается строкой `ВЕРДИКТ: OK|FAIL`. FAIL переделывается до N раз, затем уходит в «брак». По браку есть кнопка «Ещё проход». Очередь продолжается с места после рестарта, а в конце Диме приходит итог.
4. **Рутины** — существующие «Расписания» получают агента (роль, движок, модель) и итог прогона Диме пушем и в Telegram, а не в лог.
5. **Запрос ключа** — агент просит секрет по имени. Дима вводит значение в скрытое поле в «Ждут тебя», оно уходит в файл секретов. Агент узнаёт только имя, само значение он не видит никогда.
6. **Разбор** — документ: все возможности Grok Bot, где и чем он помог в проектах, что из этого теперь есть в Neo3 и чего нет (с причиной).

## Решения по реализации

- **Роль — скрытый блок в первом сообщении (`<agent_brief>`)**, а не системный промпт. Так одна реализация работает на трёх движках. Блок срезает `stripAgentOnlyBlocks` везде, где текст видит человек: так уже сделано с `<screenshot_context>`.
- **Агенты — своя таблица** со связями: агент ↔ сессия, версии памяти. `workspace_records` не подходит, потому что есть внешние ключи и выборки по сессии.
- **Чат с агентом стартует на сервере** через свой run control (новый `access.kind:'agent'`) по образцу `createThreadRunControl`. Так у него есть статус, «Стоп» и «Ждут тебя», а сам чат обычный.
- **Конвейер работает внутри сервера**: свой тик по образцу `duet.runtime.ts`, состояние в SQLite. Исполнитель — `runHeadlessPrompt` с новым актором `queue` (аудит и расход уже есть). Внешние планировщики ОС тут не нужны: очередь живёт, пока жив сервер, и продолжается после рестарта.
- **Рутины = расширение `schedules`**: колонки `agent_id`, `notify`, `last_result`, `notified_at`. Второго планировщика нет. Итог досылает сторож сервера по `last_run_at > notified_at`: раннер launchd работает вне сервера, и пуш оттуда ненадёжен.
- **Запрос ключа** идёт через `workspace_action`, поверх того же `secrets-stash`. Карточка в «Ждут тебя» — новая секция хаба (`hubSections.ts`). Значение передаётся одним POST по HTTPS-сессии админа и нигде не хранится, кроме файла секретов.
- **Уведомления** устроены по схеме `notify()` дуэта: пуш + Telegram, код `queue.done` / `schedule.result`, переход в панель через `?panel=`.

## Вне рамок

| Возможность Grok Bot | Почему не сейчас |
|---|---|
| Облачная VM с браузером на аккаунт | уже есть по-своему: Neo3 сам работает на маке (Safari вживую, `browser-use`), на VPS — Крабик; общая VM с общими куками — это как раз грабля Grok Bot |
| Routines по событию (Slack, GitHub, Teams) | в проектах Димы ни разу не сработали («молча не срабатывают»); событийных источников у Neo3 сейчас нет — следующий заход |
| Skills обучением показом (запись браузера) | в проектах не использовались ни разу; Safari не даёт JS из Apple Events — запись действий не снять |
| Auto-review rules по условию | у Neo3 есть режимы разрешений и «Разрешить и запомнить»; текстовые границы агента живут в его роли и памяти; условный движок одобрений — следующий заход |
| Групповой чат ботов в одном окне | сводка штаба («Треды готовы») + полоса тредов покрывают то, что использовалось; общий чат 2–6 ботов в проектах давал шум и жёг квоту |
| Бот сам создаёт ботов | штаб открывает помощников по имени готовых агентов; создание агентов агентом не даём — системные роли бесконтрольно плодились бы (у Grok Bot их потом нельзя было править) |
| Генерация картинок/видео внутри бота | это квота Grok Bot/Imagine, а не возможность оболочки; генерации через grok.com в Safari остаются как были |
| Плагины Cursor Marketplace, remote MCP | MCP и навыки в Neo3 уже есть (`mcp.service.ts`, `skills.service.ts`) |
| Клиенты macOS/Windows/iPhone | Neo3 уже веб + PWA + Android-приложение |
