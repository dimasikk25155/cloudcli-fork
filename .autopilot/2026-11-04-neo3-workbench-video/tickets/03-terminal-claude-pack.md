## Что должно заработать

В терминальном Claude Code внизу строка состояния: модель, заполненность контекста, 5-часовое и недельное окна (с кэшем ≤60 с, без сетевого запроса на каждое обновление; источники — те же, что у Neo3: см. `server/shared/claude-usage.ts`). Навыки: `/skill-doctor` (аудит навыков: дубли, пустые описания, битые ссылки, конфликты — только отчёт), `/setup-doctor` (проверка движков, MCP, регистрации neo3-threads, Ollama-туннеля, диска, службы Neo3 — отчётом, без показа ключей), `/advisor` (вызвать сильную модель для трудного решения с явным лимитом расхода), `/jev` (проверка картинок через `scripts/visual-qa/qa.py` из штаба: по умолчанию dry-run; платный `--execute` только по явной просьбе). Для Codex — те же `skill-doctor` и `jev` в его каталоге навыков, если он существует (проверить, как Neo3 читает навыки Codex — `server/modules/providers/list/codex/codex-skills.ts`). Для Grok — выяснить, есть ли у Grok CLI каталог навыков; если нет — инструкция запуска Jev в `docs/claude-code-terminal-pack.md` и строка для общего промпта Neo3 не добавляется автоматически (ограничение в отчёт).

Правка `~/.claude/settings.json`: сначала копия `~/.claude/settings.json.bak-20261104`, затем только ключ `statusLine` (если там уже есть statusLine — сохранить прежний в документе и спросить через отчёт, не заменять молча). Ничего в `~/.claude` не удалять и не переносить. Имена не перекрывают встроенные команды Claude Code (проверить список встроенных: `/doctor`, `/status`, `/context` и т.д.).
