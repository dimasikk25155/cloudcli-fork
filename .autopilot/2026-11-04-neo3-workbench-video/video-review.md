# Ролик Claude Code 2.0: полезные моды и возможности для Neo3

Источник: [Никита Велс — Claude Code 2.0: что РЕАЛЬНО поменялось, а что просто хайп](https://www.youtube.com/watch?v=Xq9YfQV8C-o).
Исследовано 04.11.2026: полная русская авторасшифровка, все листы раскадровки, крупные экраны в Safari. Подробности визуального просмотра — `reference.md`.

Это разбор продемонстрированного автором, а не подтверждение текущей доступности функций Anthropic в любом аккаунте. Названия моделей, тарифы и утверждения о качестве handoff/compact из речи не принимаются за проверенные технические факты. В начале автор говорит о десяти изменениях, затем нумерует одиннадцать: последнее — группа собственных модов.

## Что подтверждено в текущем коде Neo3

Это проверка исходников 04.11.2026, не пользовательский E2E и не новый выпуск.

- `src/components/main-content/view/subcomponents/mainContentTabs.ts`: уже есть Чат/Терминал/Файлы/Статистика, плагины, Автопилот. Новая система должна расширять существующую оболочку.
- `src/components/agent-workspace/AgentWorkspacePanel.tsx`: уже есть Мой день/Почта/Документы/Знания/Команда/Заявки. Не создавать параллельную несвязанную копию документов и задач.
- `src/components/attention/view/AttentionHubView.tsx`: общий список по состояниям, проекту и провайдеру, переход в сессию, отметка прочитанного. Это основа Session Hub.
- `src/components/chat/view/subcomponents/TokenUsageSummary.tsx`: занятость относительно окна выбранной модели; расход отдельно. Не подменять показатель накопленными токенами.
- `src/components/chat/view/subcomponents/CodexUsageLimitsBadge.tsx`: окна Codex с источником и временем обновления. Рядом есть `UsageLimitsBadge.tsx` для существующего механизма лимитов Claude.
- Проектные инструкции описывают серверные modules/threads, auto-relay, session-links, file-preview, code-status, notifications и общую систему модов. При проектировании следующего этапа точные API должны быть перепроверены по исходникам.
- Поиск строк btw/side-chat/skill-doctor/advisor в src/server/shared не нашёл выделенной реализации этих функций. Это предварительный результат поиска, не доказательство отсутствия любых аналогов.

## Предлагаемый порядок реализации после одного брифинга

1. Общий «Рабочий стол» и инспектор сессии: собрать имеющиеся статусы, файлы, результаты, контекст; обеспечить светлую/тёмную тему и телефон.
2. Реестр вкладок результатов и артефактов: сохраняемые панели с документами, HTML-инфографикой и презентациями, источник в чате, безопасное превью. Связать с существующими документами и файловым просмотром.
3. Общие инструменты управления рабочим местом для Claude/Codex/Grok: ограниченные команды, привязка к пользователю/проекту/сессии, проверка возможностей движка.
4. Побочные диалоги, вложенность, второй экран; ни остановки исходного прогона, ни случайной отправки в другую сессию.
5. Мастер-сессия и сводные ответы с согласованной областью доступа; использовать существующий жизненный цикл вопросов.
6. Диагностика навыков и окружения, советник; профиль настроек с предварительным просмотром. Пункты облачного исполнения, Motion, sleep/Remote Control получить явный статус и объяснение границ.
7. Регрессионные тесты и изолированные сборки; отдельные сценарии Claude, Codex, Grok; независимая приёмка по исходному брифу. Публичную выкатку не подменять локальной готовностью.

Окончательная спецификация и обязательства по каждому пункту появляются после ответов на три развилки в `briefing.md`. Никакой пункт из каталога пока не объявлен реализованным или снятым.
