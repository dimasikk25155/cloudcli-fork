# Neo3 improvement ideas integration map

Read-only exploration, 2026-11-02. No source/runtime/database edits made.

## Smallest complete design

A separate admin-only mod `modImprovementIdeas` keeps assistant improvement suggestions independently of the existing one-note-per-session memory service. A deterministic parser extracts actual `💡 Что можно улучшить дальше:` sections, without LLM calls. Persistent rows retain exact suggestion text, owner, project, source app session/message, timestamps, decision and vault-write result. Suggestions are proposals, never facts about completed work. UI shows compact session cards above composer, with `Реализовать` and `Позже`, a saved/error status, and an expandable saved list so deferred ideas are recoverable.

Use server capture on completed runs; no browser must stay open. Never start implementation from capture. Only the authenticated button action may start one ordinary chat turn, and only when no run is already active. Duplicate button posts must not spawn duplicates. Do not call a started task completed merely because it started or its run exited successfully; show `Запущено` until actual outcome is known.

## Exact seams

- `server/modules/websocket/services/chat-run-registry.service.ts`: `decorateAndRecordEvent(run, message)` is the single provider-independent event sink. `run` has appSessionId, provider, userId, projectId, events; complete is accepted once, late events dropped. After buffering the terminal complete, fire best-effort capture. Errors cannot break chat. Run event buffer is capped at 5000; either accumulate candidate assistant blocks separately as events arrive, or consume complete text events and keep a bounded candidate collection; do not rely on all early progress messages remaining in events for very long runs.
- Text event shape: `kind:'text', role:'assistant', content:string`. Providers also send `stream_delta`; see aggregation in `server/modules/session-attention/session-attention.service.ts`. Snapshot text plus deltas need dedup. Extract all completed assistant blocks, not just final reply if requirement is every improvement.
- Persisted-history fallback: `sessionsService.fetchHistory(sessionId,{})`, imported from `server/modules/providers/services/sessions.service.ts`; returns normalized messages. JSONL may lag immediately at completion, so primary capture should be live. GET-time optional idempotent import allows recent old-session ideas to appear; do not rescan all archives globally.
- `shared/reply-turn.ts` handles last assistant reply, but deliberately returns only last block; not sufficient for every suggestion in a run.
- `server/modules/websocket/services/chat-websocket.service.ts`: private `beginChatSend(ws,userId,userRole,data,dependencies,access)` returns `{started:false}` or `{started:true,finished:Promise}`. It has the per-session atomic in-memory run guard and normal provider/jail/meter/thread behaviors. `createDetachedConnection()` exists. Add exported `createIdeaRunControl(dependencies)` analogous to `createAutoRelayRunControl` / `createThreadRunControl`, with fresh admin + canAccessSession check and dedicated access kind, not untrusted reuse of `verified-answer`.
- `server/modules/auto-relay/run-options.ts`: `lastRunOptions(sessionId)` returns last person-started model, effort, permissionMode, workMode, toolsSettings, skipPermissions. Memory only; after restart fall back to session DB model/effort and normal permissions, never silently widen permissions. Explicit plan-only state cannot execute; report needing execution mode or use reviewed current composer options. `beginChatSend` remembers options only for socket runs; service start must preserve options deliberately.
- Wire run control in `server/index.js` near lines 188-196 (`pendingAnswers.setEngine`, `threadsService.setRunControl`, `autoRelayService.setRunControl`). Register authenticated router near `/api/memory-suggestions`.
- Server access: `isAdminUser(user)` + `canUserAccessSession(user,sessionId)` in `server/shared/project-access.ts` read role from DB. Do not trust request role. Use `isModOn(userId,'modImprovementIdeas')` both at capture and every mutation.
- DB style: `server/modules/database/repositories/memory-suggestions.db.ts` uses `getConnection()`; export new repository from `database/index.ts`; new schema constant in `schema.ts` must be included in both initial SQL and `migrations.ts` (existing DB requires explicit `db.exec`). Unique owner+project+normalized suggestion fingerprint prevents replay duplicate cards; source info separately retains origin. Atomic SQL status claim on implement guards multi-tab clicks; if run refuses busy release claim; crash during claim should become uncertain, never automatically retry execution.
- Vault: `server/modules/memory-suggestions/vault-writer.ts` gives default `vaultDir()`, traversal/symlink checks, `writeVaultNote()` exclusive creation. It NEVER updates existing notes and suffixes duplicates, so unsuitable as-is for stable per-project ideas ledger. Use a dedicated safe generated-ledger writer with stable server-derived filename, marker ownership check, atomic same-folder write, rejection of traversal/symlinks and unowned files, and one managed section preserving human edits. Keep text sanitized with shared secret detection/redaction before DB/vault. A missing/unwritable vault must keep DB idea and show unsaved/error/retry; not claim Obsidian saved. One ledger per project avoids thousands of one-line notes.
- UI minimal mount: `src/components/chat/view/ChatInterface.tsx`, `relayBand` slot around line 848, alongside `CrabSquadBand` / `RelayBand`, rendered above composer. Add standalone `src/components/improvement-ideas/IdeaCards.tsx` + hook. `chipsSessionId` = selectedSession.id || currentSessionId; `isProcessing` prevents action while running. `useAuth()` admin and `useModEnabled()` gate fetching and visibility. `authenticatedFetch()` is standard.
- Realtime pattern: `src/components/attention/memory/useMemorySuggestions.ts`: `useWebSocket().subscribe` listens for content-free change frame or reconnect; GET carries filtered content. Add new kind to server/shared/types.ts + src/types/app.ts if using a frame. NEVER add service frame to `CHAT_ROW_KINDS`. Alternatively re-read on `complete` and reconnect plus limited safety poll.
- `shared/mods.ts`: add key and MODS card; settings automatically show it, database preference allowlist imports MOD_KEYS. No individual settings UI changes needed.

## Suggested public contract

`GET /api/improvement-ideas?sessionId=...` -> `{ideas:[{id,sessionId,projectName,text,status:'proposed'|'later'|'starting'|'started',createdAt,vaultPath?,vaultError?}]}`.
`POST /api/improvement-ideas/:id/decision {action:'implement'|'later'}` -> current idea + started flag. Authenticated admin only; foreign session/mod-off denied; busy -> 409 with no consumed approval. Already started -> return prior result without another run.
`POST /api/improvement-ideas/:id/sync` retries failed vault write without launching work.
Use approved text from DB, not client-supplied text, for execution prompt: user approves exactly the quoted idea in this project; preserve prior constraints/budget/time; this is no blanket approval to publish/spend/delete.

## Minimum meaningful checks

Parser exact headings / Markdown / multiline / signature terminator / multiple blocks / stream vs snapshot duplicate / no idea. Capture no browser / mod-off / non-admin / secret scrubbing / replay idempotence. Decision concurrent double posts / busy retry / ownership / mod-off / run failure not called done. Vault absence, outside symlink, existing unowned file, retry and stable managed update. UI pending/error/disabled, deferred list retained, success refresh. Gateway integration tests prove correct provider/model/effort/options and no permission widening. All tests temporary HOME/DATABASE_PATH and vault root; no imports against live auth.db.
