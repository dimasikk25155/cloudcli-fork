# Идеи улучшений и проверка режима

## Задача
Проверить, действительно ли Codex продолжает работу после плана, и перестать терять предложения «Что можно улучшить дальше».

## Проверка режима
R01: сверить работающий код, сохранённые доказательства реального теста planBypass и целевые тесты. Если сбой воспроизводится, исправить и повторить проверку. Чётко отличать planBypass одного хода от переключения двух ходов.
R02: объяснить, что видимый «Автопилот» задаёт процесс сборки, а «Планирование + обход» — права и продолжение после плана; назвать проверенную комбинацию.

## Идеи
R03: новый встроенный мод «Идеи улучшений» (modImprovementIdeas), включён по умолчанию, только администратор. Не зависит от локальной модели. Извлекать предложения из завершённых текстов ассистента после явного маркера «💡 Что можно улучшить дальше:». Работает для Claude/Codex/Grok через общий серверный поток. Повторы того же текста в том же проекте не создают новую идею. Выключение прекращает сбор и запрещает запуск.

## Память
R04: постоянно хранить идеи с проектом, исходным чатом, датой, текстом и статусом. Автоматически сохранять в существующий Obsidian vault в собственный реестр, доступный rg/чтению будущим агентам, без перезаписи чужих заметок. Чётко маркировать предложение как предложение, не как сделанную работу.
R05: будущий агент по вопросу пользователя ищет название проекта/слова идеи через rg -li в wiki/ideas, читает реестр с текущими статусами и ссылается на исходный чат. Проверка: найти сохранённую тестовую идею текстовым поиском после перезапуска сервиса. При недоступном vault идея не теряется: остаётся в хранилище, пользователь видит ошибку экспорта/повторную попытку. Обновлять статус той же записи при одобрении. Не сохранять секреты; пути только внутри vault. Не добавлять сюда всю историю автоматически: сбор с момента включения, имеющиеся идеи доступны из сохранённых карточек/реестра.

## Одобрение
R06: компактные карточки в текущем чате над полем ввода с полным текстом идеи и кнопками «Реализовать», «Позже». «Реализовать» сервером проверяет админа, доступ к исходной сессии, включённость мода и отсутствие активного прогона. Одно нажатие запускает работу с точным текстом идеи в том же контексте проекта и текущими настройками модели/effort. Не спрашивать подтверждение повторно. Повторный клик/запрос не создаёт второй прогон. Если сессия занята — видимая понятная ошибка без потери идеи. «Позже» сохраняет идею, допускает реализацию в будущем. Состояния: предложено, отложено, запуск, запущено/ошибка. Никогда не называть реализацию завершённой только по успешной отправке запроса. После перезагрузки карточки восстанавливаются.

## Решения по реализации
Существующие TypeScript/React/Express и SQLite либо атомарное локальное хранилище проекта, без новых пакетов. Единая серверная точка run-registry, текущий beginChatSend через узкий run-control, серверный mod guard и существующий project-access. UI в стиле существующих встроенных карточек и кнопок; не делать редизайн всего приложения. Новые файлы модульно, текущие несвязанные правки не трогать. Детали контрактов — interfaces.md.

## Вне рамок
Публикация/перезапуск Neo3 требует отдельного явного согласования; подготовить проверенный результат без изменения dist/dist-server. Не исправлять дубль сообщений предыдущего вопроса без отдельного scope. Не сканировать старые чаты массово, не запускать идеи без клика, не менять общие системные инструкции.

## Открытые места
Нет блокирующих продуктовых вопросов. Реестр автоматический, исполнение — только по нажатию. Граница проверки UI/производства будет явно указана.
