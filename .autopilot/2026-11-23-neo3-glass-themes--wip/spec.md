# Спецификация: Neo3 на телефоне — стекло, 6 тем, нижняя панель, «Инструменты»

## Задача

Дима поставил Neo3 на домашний экран айфона через Safari. Темы почти не отличаются
одна от другой («дизайн у тем практически идентичный»). В боковой шторке висит блок
«Меню» из двенадцати экранов, а нажимает он там только «Настройки» («оно по сути
бесполезное»). Хочется вида как у приложения Grok: плавающие полупрозрачные кнопки,
строка внизу, поле ввода стеклянной карточкой — и так во всех темах. Проверять надо
без его айфона.

## Решение

- Тем становится шесть, и у каждой свой характер: шрифт, форма, тени, материал.
- Во всех шести — один стеклянный материал: плавающие кнопки, пилюли, карточка ввода.
- На телефоне внизу «Домой» и шторки проектов плавает панель: Домой · Проекты · поиск ·
  новый чат · настройки. В открытом чате её нет.
- Блок «Меню» уходит из шторки. «Настройки» — отдельная кнопка. Все двенадцать экранов
  живут во вкладке «Инструменты» настроек, у каждого написано, для чего он.
- Тема — своя на каждом устройстве; остальные настройки общие.
- Тему выбирают карточками с превью.
- «Свой тестовый» вместо айфона Димы — это стенд: отдельный экземпляр сборки и встроенный
  WebKit-браузер Neo3 с окном шириной айфона (тот же движок, что у Safari на телефоне).
- Пересмотр внешних видов касается всего приложения: темы и стекло — общие значения, их
  получают и телефон, и компьютер. Раскладка меняется только на телефоне.

## Эталон

Три скриншота Димы и его слова — в `reference.md`: список чатов Grok (плавающие круглые
кнопки и пилюля поиска поверх списка), пустой чат Grok (поле ввода карточкой с пилюлями
внутри), блок «Меню» Neo3 как есть. Истории 21–31 меряются по ним; исполнители таска,
который строит экран, открывают сами файлы снимков.

## Слова

- **Нижняя панель** — плавающий ряд стеклянных кнопок внизу экрана телефона.
- **Шторка** — боковая панель со списком проектов и чатов, на телефоне выезжает слева.
- **Стекло** — общий материал: полупрозрачный фон + размытие + насыщенность + светлая кромка + тень.
- **Вариант «Неона»** — пара «цвет акцента + фото-обои» внутри темы «Неон».
- **Инструменты** — вкладка настроек со списком экранов бывшего «Меню».
- **Стенд** — отдельный экземпляр Neo3 из рабочей копии на свободном порту с временной базой.
- «Холст», «Рабочий стол», «Конвейер», «Сценарии» — как в `CONTEXT.md`.

## Решения по реализации

- **Стекло — значения темы, а не стили компонентов.** Набор `--glass-*` в каждом блоке темы
  и четыре класса в `src/index.css`. Почему: одно место правит вид во всех темах; компоненты
  перестают сочинять размытие сами.
- **«Неон» — одна тема + атрибут варианта** (`data-theme-variant` на `<html>`). Вариант
  задаёт цвет акцента и фото. Почему: восемь копий одного шаблона превращаются в восемь
  коротких блоков по три-четыре значения.
- **Подмена старых id — чистая функция `migrateThemeId`** с таблицей, одна на клиенте;
  скрипт до первой отрисовки в `index.html` держит свою копию таблицы, тест сверяет копии
  (как сейчас сверяется список светлых тем). Почему: скрипт до отрисовки не может импортировать модуль.
- **Тема — на устройстве.** Клиент перестаёт применять тему из ответа сервера, если на
  устройстве она уже есть; запись на сервер остаётся (стартовая для новых устройств).
  Вариант «Неона» хранится на устройстве отдельно от общих `themeBackgrounds`.
  Почему: «каждому устройству своя тема, остальные настройки одинаковые».
- **Тонкая настройка убранных тем не переносится** — записи с убранными id отбрасываются. Почему:
  у новых тем другие исходные значения, старые поправки к ним не подходят. В отчёте — одной строкой.
- **Просьба агенту «поменяй тему»** (`settings.propose`) меняет только стартовую тему аккаунта,
  на устройстве тему переключает сам человек. Почему: прямое следствие «каждому устройству своя тема». В отчёте — одной строкой.
- **Фото прежней «Лаймовой»** — вариант «Неона» берёт её основное фото; четыре запасных остаются файлами,
  в выбор не входят. Почему: вариант = один цвет + одно фото.
- **Нижняя панель — один компонент в оболочке приложения**, видимость — чистая функция от
  «телефон / главная или шторка / клавиатура / открыт модальный экран». Почему: условия
  проверяются тестом без браузера.
- **Высота панели — переменная CSS** (`--bottom-bar-space`), её читают сетка «Домой» и список шторки.
  Почему: панель ничего не перекрывает, и убрать её можно одним условием.
- **Экраны «Меню» — один реестр** (ключ, название, значок, «для чего», кто видит), его читают
  вкладка «Инструменты» и открытие по ссылке/пушу. Почему: сейчас список и права лежат в
  подвале шторки, который исчезает.
- **Стенд — скрипт в `scripts/`**, сервер и клиент собираются во временную папку.
  Почему: `dist/` и `dist-server/` в основной копии обслуживают боевой Neo3.
- **Новых пакетов нет.** Почему: `node_modules` — общая ссылка на основную копию.
- Снимки — только встроенным WebKit-браузером Neo3 (`workspace_action` `browser.*`), после
  шага — `browser.close`. Chrome, Playwright, Safari не используются.
