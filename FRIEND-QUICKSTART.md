# CloudCLI для друга — быстрый старт

Разворачивается на его собственном VPS. Друг подключает свою личную подписку
Claude Code — она нигде не пересекается с моей, всё живёт только на его сервере.

Репозиторий кода **приватный** — GitHub не даст его просто так клонировать никому
без ключа. Два варианта, отличаются только тем, кто жмёт кнопки:

## Вариант A — ставлю я (одна команда с моего Мака)

```bash
cd "cloudcli-fork"
./provision-vps.sh root@<ip-сервера-друга> <домен> [golden-commit]
```

Пакует проверенный код прямо здесь (`git archive`, доступ к репо уже есть
локально — ключи на сервер друга даже не попадают), заливает и разворачивает
всё — пакеты, Node 22, Caddy, systemd-сервис. Несколько минут (`npm install`
+ сборка). Подходит, когда я сам под рукой у терминала.

## Вариант B — друг ставит сам (после одного 30-секундного шага от меня)

Друг сам заходит на свой VPS и запускает:

```bash
./install.sh <домен> --clone
```

Скрипт сам сгенерирует SSH-ключ на его сервере и остановится, напечатав
публичный ключ — присылает его мне, я вставляю в GitHub → репозиторий →
**Settings → Deploy keys → Add deploy key** (read-only, без права записи) —
30 секунд, разово на этот сервер. Друг жмёт Enter в терминале — скрипт сам
клонирует нужный коммит и доставляет всё дальше без моего участия.

`install.sh` сам по себе не секретный (просто bash-команды) — можно переслать
файлом в любом мессенджере.

## После установки (любым вариантом) — вручную, 2 минуты

1. Добавить DNS A-запись `<домен> → IP сервера` (через `cloudflare-dns` skill,
   если домен на neo3.ru).
2. Подождать, пока Caddy сам выпустит HTTPS-сертификат (Let's Encrypt, автоматом
   после того как DNS зарезолвится).

## Что делает друг сам

1. Открывает `https://<домен>` — первый визит = сам ставит логин/пароль
   (регистрация закрывается после первого юзера, это нормально).
2. Settings → **Агенты** → Claude → **«Войти снова»** → логинится СВОИМ
   Anthropic-аккаунтом по ссылке. Токены его личной подписки Claude Code
   тратятся только на его собственные запросы — хранится на его сервере,
   ни я, ни кто-то ещё этого не видит.
3. Пробует прислать задачу — должен получить нормальный ответ.

## Обновление уже работающего сервера

С моего Мака, одна команда — пакует текущий код, заливает, пересобирает,
перезапускает сервис и проверяет, что инстанс реально поднялся на новой версии:

```bash
./update-vps.sh root@<ip-сервера-друга>        # текущий HEAD
./update-vps.sh root@<ip-сервера-друга> <sha>  # конкретный коммит
```

Данные не трогаются: база и логины (`~/.cloudcli/`), проекты (`~/workspace/`),
настройки инстанса (`~/cloudcli/.env`) лежат вне гита и переживают обновление.

Если друг ставился вариантом B (`--clone`, на сервере есть `.git` и deploy-ключ),
он может обновиться сам, без меня:

```bash
ssh root@<его-ip>
su - cloudcli -c "cd ~/cloudcli && git pull && npm install && npm run build"
systemctl restart cloudcli && curl -s localhost:3001/health
```

Проверить, какой у него случай: `ssh root@<ip> 'ls -d /home/cloudcli/cloudcli/.git'`
— есть `.git` значит можно `git pull`, нет — только `update-vps.sh` с моей стороны.

После обновления сервера пользователю нужно **перезагрузить страницу в браузере**
(в Safari — `⌥⌘R`), иначе он останется на старом бандле.

## Если что-то не так

- Сервис не поднялся: `ssh root@<ip> systemctl status cloudcli`
- Логи: `ssh root@<ip> journalctl -u cloudcli -f`
- HTTPS не выдаётся: проверить, что DNS уже указывает на сервер
  (`dig <домен>` снаружи), Caddy сам зациклится и повторит попытку.
