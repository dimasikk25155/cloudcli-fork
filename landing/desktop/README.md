# /desktop — раздача Neo3 Desktop

Здесь лежит `latest.json` — манифест обновлений настольного приложения. Его читает
приложение при запуске и раз в 6 часов по адресу `https://cli.neo3.ru/desktop/latest.json`.

**Сейчас настоящего `latest.json` тут нет — и это правильно.** Пока файла нет, приложение
молча работает дальше, как будто нет сети. Плохой вариант — выложить манифест, в котором
собрана не та платформа: клиент на Mac увидит канал обновлений без своей сборки.

- `latest.example.json` — только пример структуры, выкладывать его нельзя.
- Настоящий файл появляется после релиза: workflow `release` в репозитории `neo3-desktop`
  собирает его из артефактов и кладёт в артефакт сборки `latest-json` (и в сам релиз).
  Скачать оттуда, положить сюда под именем `latest.json`, задеплоить лендинг.
- Локально то же самое делает `node scripts/manifest.js build <папка-со-сборкой>` —
  по умолчанию он пишет ровно в этот каталог.
- Текст объявления меняется отдельно от версии:
  `npm run notice "Сервер на профилактике до 14:00"`, снять — `npm run notice -- --clear`.
  Другой файл — только после двойного тире: `npm run notice -- --file <путь> "текст"`.

Деплой лендинга — руками, CI сюда ничего не публикует.

## Страница `index.html` и редиректы

`index.html` — страница скачивания `https://cli.neo3.ru/desktop/`. Версию на кнопках она берёт
из `latest.json` рядом: пока файла нет, стоит «уточняется». Появился `latest.json` — версия
проставится сама, страницу править не надо.

Размер показывается только у Windows: в манифесте `win32-x64` — это ровно тот `.exe`, который
скачивается по кнопке. У Mac в манифесте лежит вес zip-архива обновления, а не `.dmg`, поэтому
там честнее заглушка. Хотите цифру — возьмите вес `Neo3-mac-arm64.dmg` со страницы релиза
и впишите руками в `index.html`.

Кнопки ведут на редиректы из `../vercel.json` (клиент не видит GitHub до самого скачивания):

| Адрес | Файл релиза | Кому |
|---|---|---|
| `/desktop/mac` | `Neo3-mac-arm64.dmg` | маки с конца 2020 (Apple M1–M4) |
| `/desktop/mac-intel` | `Neo3-mac-x64.dmg` | старые маки на Intel |
| `/desktop/windows` | `Neo3-win-x64.exe` | Windows |

**Номера версии в этих адресах нет и быть не должно.** Все три ведут на
`releases/latest/download/<постоянное имя>` — GitHub сам отдаёт файл из последнего релиза.
Постоянные имена кладёт в релиз workflow `release` (рядом с обычными, версионными). Ничего
перебивать при релизе не нужно — именно поэтому так и сделано: забытая правка раздавала бы
прошлую сборку молча, без 404.

Порядок выкладки:

1. Скачать `latest.json` из артефактов workflow → положить сюда.
2. Задеплоить лендинг.
3. Открыть `/desktop/`, нажать обе кнопки — должно начаться реальное скачивание нужной сборки.
4. Там же убедиться, что версия и размер подставились вместо «уточняется» — иначе заглушка
   останется навсегда и никто этого не заметит.

Редиректы намеренно временные (`"permanent": false`): постоянный 308 браузеры кэшируют, и после
релиза кнопка ещё неделю тянула бы предыдущую сборку.
