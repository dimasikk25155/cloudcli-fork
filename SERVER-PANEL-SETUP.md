# Панель «Сервер» — что включить на машине

Панель показывает состояние машины, на которой запущен Neo3: нагрузку, живость
сервисов, логи, что установлено. Кнопка **Сервер** в левом нижнем углу —
видна только владельцу (роль `admin`), остальные пользователи её не увидят.

Часть данных читается без всяких настроек, часть требует прав. Панель никогда
не падает из-за нехватки прав — она честно пишет, чего ей не хватает.

## Что работает сразу

- нагрузка: процессор, память, диск, сеть, аптайм, load average;
- список всех сервисов systemd: живой / упал / перезапускается / выключен,
  сколько работает, сколько ест памяти, сколько раз перезапускался;
- открытые порты, тяжёлые процессы, размер папок в `/opt`, версии Node/Python/PostgreSQL;
- карточка Windows-машины, если она шлёт отчёты в «Пульт жизни»
  (`/opt/pulse/data/windows.json`).

## Что требует прав

Neo3 работает не от root — иначе любая дыра в нём стала бы дырой во всей машине.
Поэтому две возможности нужно выдать отдельно.

Выполнить **от root** один раз, подставив пользователя, под которым запущен Neo3
(смотрится в `systemctl show neo3 --property=User`, по умолчанию `agents`):

```bash
USER_NAME=agents

# 1. Читать системный журнал — иначе вкладка «Логи» будет пустой
usermod -aG adm,systemd-journal "$USER_NAME"

# 2. Включать и выключать сервисы кнопками в панели
cat >/etc/sudoers.d/neo3-server-panel <<EOF
$USER_NAME ALL=(root) NOPASSWD: /usr/bin/systemctl start *, /usr/bin/systemctl stop *, /usr/bin/systemctl restart *, /usr/bin/systemctl enable *, /usr/bin/systemctl disable *
EOF
chmod 440 /etc/sudoers.d/neo3-server-panel
visudo -c   # должно ответить "parsed OK"

# 3. Видеть docker-контейнеры (не обязательно)
usermod -aG docker "$USER_NAME"

# 4. Перезапустить Neo3 — новые группы подхватываются только при старте
systemctl restart neo3
```

## Алерты в Телеграм

Вкладка **Алерты** в панели. Раз в минуту проверяются сервисы, диски, память и
отчёты других машин. Сообщение уходит **один раз** — когда сломалось и когда
починилось, а не каждую минуту. После перезапуска Neo3 приходит одна сводка,
а не простыня по каждой давно лежащей проблеме.

Что нужно включить:

1. Настройки → Telegram → вставить токен бота (подойдёт тот же `@neo3_panel_bot`,
   его токен лежит в `/opt/pulse/pulse.env`, строка `CRYPTO_BOT_TOKEN`).
2. Написать боту в Телеграме — чат привяжется сам.
3. Вкладка Алерты → галочка «Писать в Телеграм» → кнопка **Проверить связь**.

Порог «перезапусков подряд» считает `NRestarts` у systemd. Это накопительный
счётчик с момента загрузки, а не «за час» — сервис с сотнями рестартов заведомо
падает по кругу, даже если прямо сейчас показывает `active`.

Во вкладке Алерты есть список **«О чём не сообщать»**: сломанный сервис, который
чинить сейчас некогда, отключается галочкой и перестаёт долбить в чат. Остальные
проблемы при этом продолжают приходить.

## Почему упал: разбор без всяких моделей

Сломанный сервис в «Обзоре» показывает не только имя, но и причину падения с
последней строкой ошибки. Причина определяется правилами по тексту лога и кодам
systemd — никаких запросов к языковым моделям: панель должна отвечать мгновенно,
одинаково и не тратить лимиты.

Что панель узнаёт словами: отозванная сессия Telegram (`AuthKeyDuplicatedError`),
мёртвый токен бота, вторая копия бота на другой машине, нехватка библиотеки
Python или пакета Node, занятый порт, OOM, отказ в правах, пропавший файл,
недоступный домен, ожидание ввода с клавиатуры, неверный путь в `ExecStart`.
Если правило не сработало — панель честно пишет «причину определить не вышло»
и не выдумывает.

Новые правила добавляются в `RULES` в `server/modules/vps/vps.service.ts`, к
каждому нужен тест в `server/modules/vps/tests/vps.service.test.ts`.

## Логи: журнал и собственные файлы сервисов

Вкладка «Логи» открывается сразу на сломанном сервисе, а не на пустом выборе.
Два момента, из-за которых логи раньше казались пустыми:

- Сервис с `StandardOutput=append:/path/file.log` в журнал не пишет ничего.
  Панель читает путь из юнита и показывает хвост этого файла, подписывая
  источник.
- Приоритет journalctl (`-p`) не используется: боты пишут ошибки в stdout с
  уровнем info, и фильтр «только ошибки» по приоритету не находил ничего.
  Уровень определяется по тексту строки.

Служебные строки systemd («перезапуск №13481») по умолчанию скрыты — у падающего
бота они составляют почти весь журнал. Кнопка «Служебные скрыты» их возвращает.
Ещё во вкладке: поиск по строкам, живой хвост (обновление раз в 3 секунды),
копирование и скачивание — чтобы отдать лог агенту в чат.

## Переезд с «Пульта жизни» (/opt/pulse)

Панель умеет то же, что телеграм-бот Пульса, плюс показывает это в браузере.
Пока Пульс жив, панель читает его файлы (`/opt/pulse/data/*.json`) — карточки
чужих машин помечены «через Пульс». Как только машина начнёт слать отчёт в Neo3,
метка исчезнет сама. Дня «всё переключили и сломалось» не существует.

**Порядок отключения — именно такой:**

1. Панель работает, права выданы, алерты проверены кнопкой.
2. На Windows в `C:\claude-workspace\server-guardian\pulse_report.ps1` поменять
   первые две строки — адрес и токен (токен берётся во вкладке Алерты):
   ```powershell
   $URL="http://100.69.220.92:3001/api/vps/ingest"
   $TOKEN="<токен из вкладки Алерты>"
   ```
   (третью строку, которая читает `PULSE_TOKEN` из `pulse.env`, удалить — иначе
   она перетрёт новый токен).
3. **Обязательно** в `vps_watch.ps1` поменять адрес проверки, иначе внешний
   сторож будет считать выключенный Пульс за упавший VPS и слать ложные тревоги:
   ```powershell
   $HEALTH="http://100.69.220.92:3001/health"
   ```
   Этот сторож — единственный, кто заметит падение самого Neo3, поэтому его
   выключать нельзя ни в коем случае.
4. Убедиться, что во вкладке Алерты карточка Windows больше не помечена
   «через Пульс» (значит отчёты идут напрямую).
5. Только теперь гасить Пульс:
   ```bash
   systemctl disable --now pulse-bot pulse-dashboard pulse-agent
   ```
   Файлы в `/opt/pulse` не удалять — пусть полежат месяц.

## Что панель НЕ трогает

Управление отключено — кнопок нет, только просмотр — у всего, что установлено
не вручную (юниты вне `/etc/systemd/system/`), и у списка защищённых сервисов:

`neo3`, `ssh`, `tailscaled`, `docker`, `containerd`, все `cloudflared*`,
`systemd-*`, `user@*`, `getty@*`.

Причина простая: остановив любой из них, вы отрежете себе доступ к самой панели.
Такие сервисы помечены серым словом «защищён». Список задан в
`server/modules/vps/vps.service.ts` (`PROTECTED_UNITS` и `PROTECTED_PREFIXES`).

## Где что лежит

| Файл | Что делает |
|---|---|
| `server/modules/vps/vps.service.ts` | сбор метрик, systemd, логи, инвентарь |
| `server/modules/vps/vps.routes.ts` | HTTP-эндпоинты `/api/vps/*` (только для admin) |
| `src/components/server/ServerPanel.tsx` | сама панель |
| `src/components/sidebar/view/subcomponents/SidebarFooter.tsx` | кнопка входа |

Панель рассчитана на Linux с systemd. На macOS и Windows вкладки нагрузки
работают, а сервисы и логи — нет: там нет systemd.
