# Совместимость Neo3 с Codex — аудит 02.11.2026

## Результат и границы

Исправления подготовлены в ветке `audit/codex-compat-20261102`. Проверялись адаптер
Codex, клиент чата и настроек, история и поиск, модели/effort/контекст, MCP и навыки,
встроенный терминал, изоляция участников, анализатор, общие механизмы тредов,
переносов, уведомлений и модов. Полный набор тестов включает также Claude/Grok.

Это проверка исходников и реальных запусков адаптера в одноразовом окружении.
Работающий Neo3, его `dist/`, `dist-server/`, LaunchAgent и конфигурации владельца
не обновлялись. Изменения не отправлялись в GitHub. Полный пользовательский сценарий
через браузер, публичный WebSocket и push/Telegram после выкатки ещё не проверен.
Проверка не доказывает отсутствие любой теоретически возможной ошибки.

На момент аудита глобальный CLI, SDK проекта и последняя стабильная версия npm —
**0.166.0**. Переустановка не нужна; зависимости и lockfile не менялись. Установленная
версия не гарантировала совместимость: типы SDK по-прежнему разрешают значение,
которое вложенный CLI уже отвергает.

## Исправления

1. **Обычный режим не запускался.** Реальный CLI вернул
   `approval_policy = "untrusted" is no longer supported; remove this setting`.
   Режим переведён на поддерживаемый `on-request`, песочница `workspace-write`
   сохранена. В интерфейсе объяснено, что дополнительные интерактивные разрешения
   текущий exec-адаптер не принимает; обход ограничений автоматически не включается.
2. **Ложный успех при ошибке или оборванном потоке.** Фатальный верхнеуровневый
   `error`, отсутствие `turn.completed`, сетевой `AbortError` больше не превращаются
   в успешное завершение. Отмена определяется собственным сигналом остановки.
3. **Граница между ходами.** Единственное событие `complete` публикуется после
   освобождения прогона. Завершение предыдущего хода не меняет состояние нового.
   Повторная остановка уже законченного хода отклоняется; внешняя отмена работает
   даже до получения нативного id. Обычный вопрос завершает ход без ожидания в цикле.
4. **Проверка входа и версии процесса.** Статус аккаунта читается через официальный
   `account/read` с `refreshToken:false`, а лимиты — через `account/rateLimits/read`.
   Оба используют бинарный файл зависимости SDK, а не случайный `codex` из PATH.
   Добавлен общий ограниченный по времени RPC-клиент с закрытием дочернего процесса.
   Сохранён UI-контракт `api_key`; значения токенов не извлекаются в ответ.
5. **Отдельная папка Codex (`CODEX_HOME`).** Её используют каталог моделей,
   конфигурация, MCP, навыки, синхронизация/наблюдение истории, регистрация тредов,
   резервное чтение контекста и подготовка командной песочницы. При смене папки
   существующая ссылка общего входа участника переключается на новый источник;
   обычный файл его собственного входа не заменяется. Тестовый runner сбрасывает
   наследуемый производственный `CODEX_HOME`.
6. **Редактирование MCP теряло ограничения.** Сохраняются `enabled:false`, списки
   разрешённых/запрещённых инструментов, правила подтверждения, таймауты и незнакомые
   интерфейсу поля. Смена транспорта убирает несовместимые поля; таймаут HTTP
   корректно читается и записывается. Поведение остальных провайдеров сохранено.
7. **Навыки из промежуточных папок.** Поиск `.agents/skills` проходит через всех
   родителей рабочей папки до корня репозитория, а не только cwd/parent/root.
8. **История и вложения.** Идентификаторы строк стабильны между чтениями.
   Смешанные локальные и встроенные картинки не теряются. Некорректные элементы
   изображения пропускаются. Фатальные события Codex отображаются как ошибки.
9. **Поиск по переписке.** Используется тот же классификатор реального пользовательского
   ввода, что в истории. Внедрённые AGENTS.md/контекст больше не считаются сообщениями
   пользователя; старые `event_msg` остаются доступны.
10. **Патчи из нескольких файлов.** История сохраняет исходный `apply_patch`, добавления,
    удаления, обновления и переносы файлов. Раньше изменения разных файлов склеивались
    в один фиктивный Claude `Edit`, а add/delete могли получать путь `unknown`.
11. **Анализ без инструментов.** `runCodexReadOnly` читает поток с обязательным
    успешным завершением и непустым ответом. Ошибки и обрыв больше не маскируются.
    Допустимые значения effort берутся из общего контракта SDK, включая `persistent`;
    каталог предлагает уровень только при наличии в данных модели.
12. **Настройки и первый кадр чата.** Режим работы в настройках показывается по
    возможностям backend, включая Codex/Grok. До загрузки каталога возможностей
    Codex сохраняет планирование и выбор режима. Подсказка MCP учитывает HTTP.
13. **Встроенный терминал Codex.** Запуск/возобновление используют `--no-daemon`,
    чтобы общий фоновый сервер не отделял выполнение от окружения терминала.
    Участник получает собственный `CODEX_HOME`; внутренняя песочница не вкладывается
    в уже действующую macOS-песочницу. Администратору автоматический bypass не добавлен.

## Что не является переносимой возможностью Claude

- Нативные интерактивные разрешения и `request_user_input` Codex пока не подключены
  к кнопкам Neo3/push/Telegram. Текущий SDK основан на `codex exec`; для двусторонних
  запросов нужен отдельный адаптер App Server. Вопрос обычным текстом работает.
- Отдельная кнопка остановки конкретной фоновой команды Codex отсутствует. Общая
  отмена хода поддержана; Claude `stopTask` не выдаётся за API Codex.
- Claude SDK-плагины, `neo3-guards` и таймер кэша Claude не становятся функциями Codex
  от копирования папки. Skills/MCP и пользовательские инструкции имеют свои адаптеры.
- GUI Codex Desktop, удалённое управление, каждый сторонний MCP/плагин и все модели
  аккаунта не проверялись. Этот аудит не добавляет собственный интерфейс для всех
  команд нативного TUI.
- Статус входа понимает keychain через RPC, но изолированный анализатор и общий вход
  участников пока требуют локальный `auth.json`. Проверка выполнена с таким входом;
  keychain-only конфигурация этих двух путей не подтверждена.
- VPS/Крабик не переключались, вход на VPS заново не выполнялся. Прежние противоречивые
  результаты входа в отчёте 01.11 не объявляются исправленными этим Mac-аудитом.

## Повторить проверки

Из корня форка:

```sh
npm run typecheck
TMPDIR="$(node -p 'require("node:fs").realpathSync(require("node:os").tmpdir())')" npm test
node_modules/.bin/tsx --tsconfig server/tsconfig.json scripts/verify-codex-compat.mjs --run
```

Последняя команда использует реальные модельные ходы и требует существующий вход
через `auth.json`. Создаёт отдельные HOME/БД/проект/MCP, убирает их после завершения.
Модель можно задать `NEO3_CODEX_QA_MODEL`, путь отчёта — `NEO3_CODEX_QA_REPORT`.
Значения токенов не выводятся. Итог по умолчанию: `/tmp/neo3-codex-compat-qa.json`.

Локальные свидетельства текущего аудита: `/tmp/neo3-codex-audit-20261102/` —
`baseline-tests.log`, `final-tests.log`, `final-typecheck.log`, `live-smoke-final.log`,
`live-analysis.log`, воспроизведения ошибок, проверки скриптов и изолированные сборки.
Эти временные файлы не являются постоянным хранилищем результатов.

## Применение

Для выкатки требуется отдельное согласие по правилам проекта. До неё не запускать
`npm run build`, `prebuild:server` или рестарт работающего LaunchAgent.

В начале задачи уже существовали чужие правки в документации, upgrade-скриптах,
`grok-cli.js`, `user-jail.ts` и его тесте, а также handoff-файл. Они сохранены;
совпадение исходных изменений проверено. В `user-jail.ts` добавлены только изменения
Codex поверх прежней функции Grok. Нельзя включать весь dirty tree в выпуск без разбора.

При согласованной выкатке: выделить только изменения аудита, сохранить рабочие
артефакты для отката, дождаться отсутствия активных прогонов, применить сборки и
перезапустить Mac runtime. Затем проверить публичный HTTP, обычный Codex-чат,
продолжение после обновления страницы, остановку, картинку, MCP, настройку режима
и терминал участника. Успешная сборка сама по себе эту проверку не заменяет.
