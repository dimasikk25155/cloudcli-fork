# 0008. «На сайте» — через Vercel API и реестр deploy-verify, только для админа

**Статус:** принято, 2026-10-12

## Контекст

Чип «Где мой код» должен показывать не только git, но и что выкачено (R01–R02, R26i).
Единого источника «какая версия на проде» у проектов нет: около 20 проектов Димы живут на
Vercel, остальные — VPS-боты и статика без номера версии. Ключ Vercel у Димы один, личный.
Neo3 мультиюзерный (R24i): чужой пользователь не должен ходить в Vercel от имени Димы.

## Решение

- Проект с привязкой Vercel (файл привязки в папке проекта): последняя прод-сборка через
  Vercel API. Есть SHA коммита — сверяем с HEAD и main; нет SHA — сравниваем время сборки
  со временем последнего коммита main. Там же берётся последняя превью-ссылка (R04).
- Проект без Vercel, но с адресом в реестре сайтов навыка deploy-verify: только «сайт
  отвечает / не отвечает», без версии. Нет ни того, ни другого — пункта про сайт нет.
- Сведения о сайте получает только админ; ключ читается из файла секретов Neo3.
  Остальные видят только git-часть.
- Кэш 60 секунд, сбой Vercel или сети даёт «сайт: не узнать», git-часть не страдает.

## Рассмотренные варианты

- **Свой реестр деплоев внутри Neo3** — его нужно наполнять при каждой выкатке, а
  выкатки идут мимо Neo3; данные быстро врут.
- **Опрос прод-адреса на маркер версии** — у большинства сайтов маркера нет, пришлось бы
  менять каждый проект.
- **Vercel для всех пользователей** — раскрывает данные проектов Димы по его ключу.

## Последствия

- Точная версия на сайте есть только для Vercel; для VPS и статики — лишь доступность.
- Неадмины никогда не видят состояние сайта, даже своих проектов на Vercel.
- Чип зависит от формата файла привязки Vercel и от формата реестра deploy-verify;
  смена любого из них ломает сайтовую часть (git остаётся).
- Добавление другого хостинга — отдельный источник в том же модуле, без смены контракта.
