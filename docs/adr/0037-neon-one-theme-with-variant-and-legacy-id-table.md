# 0037. «Неон» — одна тема с вариантом, убранные id заменяет таблица с копией в скрипте

**Статус:** принято

## Контекст

Тем было много, а различались они слабо. Дима попросил «меньше, но качественнее». Восемь фото-тем были копиями одного шаблона с разным цветом и обоями. Ещё три темы (красная, бежевая светлая, терракотовая) повторяли соседние.

## Решение

Остаётся шесть тем. Восемь фото-тем становятся вариантами одной темы «Неон»: вариант задаёт только цвет акцента и одно фото и хранится атрибутом `data-theme-variant` на `<html>`. Красная и терракотовая заменяются «Оранжевой», бежевая светлая — «Бирюзовой». Убранный id подменяет чистая функция по таблице; скрипт в `index.html` до первой отрисовки держит свою копию таблицы, тест сверяет обе. Неизвестный id даёт «Оранжевую». Подмена никогда не ведёт на «Светлую Claude».

## Почему

Отвергнуты восемь отдельных тем: восемь одинаковых блоков значений, восемь карточек в выборе, и все те же «почти одинаковые» темы. Отвергнуто молча сбрасывать убранный id в «Оранжевую», как делал код раньше: человек с фото-темой потерял бы свой цвет и обои. Таблица продублирована потому, что скрипт до отрисовки не может импортировать модуль, а ждать модуль значит показать вспышку чужой темы. Копию страхует тест, иначе таблицы разойдутся тихо. «Светлую Claude» Диме не включают: это его прежнее решение.

## Последствия

Таблица живёт в двух местах навсегда: добавить или убрать id можно только в обоих. Тонкая настройка убранных тем не переносится: у новых тем другие исходные значения, старые поправки не подошли бы. Файлы фото прежних тем нельзя переименовывать и удалять, их читает вариант. Из четырёх запасных фото «Лаймовой» в выбор входит только основное. Ссылки и записи на устройствах со старым id ещё долго идут через подмену.
