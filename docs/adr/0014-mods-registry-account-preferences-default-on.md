# 0014. Выключатели модов — один реестр в `shared/mods.ts`, выбор в настройках аккаунта, отсутствие ключа = включено

**Статус:** принято, 2026-10-14

## Контекст

Двенадцать модов получают выключатели (R01–R14); выбор должен действовать на всех устройствах
(R20i), а у Димы ничего не должно измениться, пока он сам не выключит (R21i).

## Решение

- Список модов (ключ, заголовок, описание, `requires`) живёт в одном модуле корневого
  `shared/mods.ts`, общем для клиента, сервера и stdio-MCP тредов. Модуль не зависит от БД.
- Там же — единственный идентификатор отказа `MOD_OFF` и единственный текст `modOffMessage`;
  все маршруты и инструменты отвечают ими.
- Выбор хранится в существующих настройках аккаунта `user_ui_preferences`; ключи реестра
  добавлены в разрешённый список. Отсутствующий ключ означает «включено» и на клиенте, и на
  сервере. Ключ крабиков `subagentCrabs` сохранён без переименования.
- Сервер читает выбор одной синхронной функцией `isModOn(userId, key)`; нет пользователя
  или ключа — `true`.

## Почему

- Отвергнуто: списки модов отдельно в карточках, клиентских и серверных проверках — двенадцать
  строк в трёх местах разойдутся.
- Отвергнуто: localStorage — не переживает смену устройства, а Дима сидит с телефона.
- Отвергнуто: отдельная таблица модов — дублирует механизм, который уже синхронизирует
  устройства (так сделаны крабики).
- Отвергнуто: явная запись «включено» при миграции — лишняя миграция; дефолт через отсутствие
  ключа даёт тот же результат без касания данных.
- Отвергнуто: единый префикс `mod*` с переименованием `subagentCrabs` — сбросил бы уже сделанный
  Димой выбор.
- `MOD_OFF` и текст в модуле без БД — иначе stdio-MCP пришлось бы тянуть серверный слой ради
  одной строки, а тексты отказа расходились бы по движкам.

## Последствия

- Ключи в базе становятся контрактом: переименовать мод без миграции нельзя — выбор
  пользователей молча сбросится на «включено».
- Дефолт «вкл» означает, что новый мод появится включённым у всех, включая клиентов форка.
- Ключ крабиков выбивается из именования `mod*` навсегда.
- Клиенты, которые разбирают ошибку по `MOD_OFF`, ломаются при смене кода; текст отказа виден
  агентам всех движков, менять его — значит менять поведение агентов.
