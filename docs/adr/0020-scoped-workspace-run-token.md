# 0020. Отдельный grant рабочего пространства для run token

**Статус:** принято

## Контекст

Выдача run token исторически зависит от `modThreads`. Передача объекта рабочего пространства агенту должна работать и при выключенных тредах, но сама по себе не должна открывать инструменты создания или отправки сообщений в треды. Контекст handoff в браузерном `sessionStorage` не является доказательством права доступа.

## Решение

Разрешать выдачу token при наличии серверного workspace grant, привязанного к пользователю, проекту, источнику и фактической сессии. Handoff получает grant, который связывается с принадлежащей пользователю сессией; при каждом инструментальном вызове повторно проверяются пользователь, сессия, проект и право на источник. Grant даёт доступ только к выбранному объекту. Разрешение не меняет проверки `spawn_thread` и `message_thread`: при выключенных тредах они остаются запрещены.

## Почему

Связать workspace с `modThreads` означало бы делать независимую функцию зависимой от переключателя тредов. Выдавать token всем workspace-вызовам или считать переданный `sourceId` полномочием — значит расширить доступ за пределы явно переданного объекта. Отдельный узкий grant разделяет эти полномочия и допускает отрицательные проверки на отсутствие доступа.

## Последствия

Handoff выполняется в два шага: сервер выдаёт grant, затем UI связывает его с обычной сессией. Без подтверждённой привязки tool-вызов отказывает. Почтовый grant не открывает весь ящик: владелец и выбранное письмо проверяются при каждом чтении. Изменения не подразумевают production-релиз или внешний E2E.
