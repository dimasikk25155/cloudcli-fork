# 0005. Маркер NEO3_SESSION и правка ~/.claude/settings.json отдельным шагом

**Статус:** принято, 2026-10-12

## Контекст

Stop-хук obsidian-memory в конце каждой сессии съедает лишний ход на полном контексте
(R29). В терминальном Claude Code хук нужен и должен остаться. Для терминала нужен ещё
хук-страж секретов на отправку промпта (R28), а в Neo3 есть свой страж в интерфейсе.
Оба хука настраиваются в `~/.claude/settings.json` — файле вне репозитория, общем для
всех сессий на машине.

## Решение

- Neo3 ставит переменную `NEO3_SESSION=1` в окружение Claude-сессий и в эмуляцию хуков
  Grok. Хук памяти и хук-страж при этой переменной выходят сразу и молча.
- Скрипт хука-стража лежит в репозитории и использует тот же общий детектор секретов,
  что и интерфейс; в ответе указывается вид секрета, без значения.
- Правка `~/.claude/settings.json` (выход хука памяти по маркеру, подключение
  хука-стража) — отдельный шаг применения с вопросом Диме, не часть сборки и тестов.

## Рассмотренные варианты

- **Удалить Stop-хук из настроек совсем** — пропадёт напоминание в терминале.
- **Отдельный каталог настроек для сессий Neo3** — расходится с общими скиллами,
  хуками и разрешениями, которыми Дима пользуется везде.
- **Править `settings.json` прямо в таске** — изменение вне репозитория без отката
  через git и без согласования, затрагивает все сессии на машине.

## Последствия

- До шага применения маркер ставится, но хук памяти в Neo3 продолжает срабатывать.
- Любой новый хук, который должен вести себя по-разному в терминале и в Neo3, опирается
  на тот же маркер.
- Если Neo3 перестанет ставить переменную, хуки молча вернутся в сессии Neo3.
