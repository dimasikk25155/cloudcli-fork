# 0026. Конфликт сохранения определяется по sha256 файла на диске

**Статус:** принято

## Контекст

Пока Дима правит макет руками, агент может изменить тот же файл. Записи артефактов в `workspace_records` имеют `revision`, и обычный обновлением записи конфликт ловится.

## Решение

`saveEdit` сравнивает sha256 файла на диске с sha версии `baseVersionN` и требует, чтобы эта версия была последней. Несовпадение — отказ 409 `ARTIFACT_EDIT_CONFLICT` с `latestVersion` в `details`. Перед записью realpath проверяется на выход из проекта и приватные сегменты. Правки Димы остаются в стеке в памяти и переигрываются на новом исходнике по отпечаткам элементов; не нашедшиеся операции пропускаются и считаются.

## Почему

Отвергнуто: ревизия записи артефакта. Агент пишет в файл напрямую, запись при этом не обновляется, и `revision` совпадёт при уже изменённом файле. Отвергнуто: блокировка файла на время правки — агент не обязан о ней знать, а зависшая правка заблокировала бы его. Хэш проверяет то, что реально будет перезаписано.

## Последствия

Проверка и запись не атомарны: между чтением sha и `writeFile` остаётся короткое окно гонки. На 409 сервер уже записал правку агента новой версией, и её нужно показать в списке. Переигрывание по отпечаткам (CSS-путь по тегам и индексам плюс начало текста) может молча пропустить операцию, если агент переписал блок. Это сообщается числом, но восстановить такие правки автоматически нельзя.
