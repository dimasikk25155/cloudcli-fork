# 0017. Другие устройства узнают о смене выключателя по пустому WS-кадру `ui_preferences_changed`

**Статус:** принято, 2026-10-14

## Контекст

Сервер гасит мод сразу после сохранения, а экран на другом устройстве (обычно телефон Димы)
держит старый выбор до перезагрузки (R20i).

## Решение

После `PUT` настроек сервер шлёт этому пользователю WS-кадр `ui_preferences_changed` без
содержимого; клиент по нему перечитывает настройки тем же GET. Кадр служебный и в
`CHAT_ROW_KINDS` не добавляется.

## Почему

- Отвергнуто: кадр с самими значениями — второй путь доставки данных в обход GET и его
  фильтров; та же схема, что у `attention_changed`, уже проверена.
- Отвергнуто: только перечитывание при открытии вкладки — телефон в фоне показывал бы
  выключенный мод.
- Отвергнуто: периодический опрос настроек — лишняя нагрузка ради редкого события, с
  задержкой до интервала.

## Последствия

- Каждая смена любой настройки аккаунта вызывает GET на всех открытых устройствах.
- Устройство без живого WS обновится только при следующем открытии или синхронизации;
  в этом окне экран и сервер расходятся (сервер прав).
- Кадр без `sessionId` не должен попасть в стор переписки — нарушение этого правила уже
  однажды обнуляло историю чата (12.10).
