# 0011. Мод-ограничитель Claude подключается опцией SDK `plugins`, а не `CLAUDE_CODE_PLUGIN_DIRS`

**Статус:** принято, 2026-10-12

## Контекст

Агент Claude часами крутит ожидание-цикл в основном потоке, и Дима не понимает, работает
он или завис (R12). В брифе предложен мод с хуком на вызов инструмента через переменную
`CLAUDE_CODE_PLUGIN_DIRS`. Neo3 запускает Claude через SDK, а на той же машине Дима
работает и с терминальным Claude.

## Решение

- Мод лежит локальной папкой в форке (`claude-plugins/neo3-guards`) и подключается
  опцией SDK `plugins` при создании каждой сессии Neo3.
- Правило: вызов Bash не в фоне, с циклом и `sleep`, и таймаут выше порога (по умолчанию
  120 с, настраивается переменной окружения) — отклоняется с подсказкой «уведи в фон
  и следи через Monitor».
- Запасной путь, если CLI в SDK-сессии мод не грузит, — хук `PreToolUse` в опциях SDK
  с тем же правилом.

## Рассмотренные варианты

- **`CLAUDE_CODE_PLUGIN_DIRS`** — тот же механизм загрузки, но переменная глобальна:
  задела бы терминального Claude и все дочерние процессы.
- **Сразу хук `PreToolUse` в опциях SDK** — работает, но правило не оформлено модом
  и не переносится отдельно; оставлен запасным.
- **Править глобальные настройки Claude** — меняет поведение вне Neo3.

## Последствия

- Ограничение действует только в сессиях Neo3; терминальный Claude его не получает.
- Мод зависит от поддержки опции `plugins` в версии SDK/CLI; при обновлении движка
  проверять, что мод грузится.
- Эвристика цикла может промахнуться в обе стороны; правило — чистая функция с тестами.
- Codex и Grok такого ограничения не имеют.
