# 0009. Связи чатов — одна пара колонок «родитель + вид связи» в таблице сессий

**Статус:** принято, 2026-10-12

## Контекст

Эстафета создаёт новый чат-продолжение старого (R08), треды создают чаты-детей агента
(R15). В обоих случаях сайдбар должен показывать связь в обе стороны, а сервер —
проверять, что ребёнок в том же проекте и у пользователя есть доступ к родителю (R24i).

## Решение

- В таблицу сессий добавлены колонки «родительская сессия» и «вид связи»
  (эстафета или тред). У сессии не больше одного родителя.
- Связь ставится только при создании сессии, с проверкой доступа к родителю и
  совпадения проекта; список проектов отдаёт связи для сайдбара.
- Эстафета и треды пользуются одним модулем `session-links`.

## Рассмотренные варианты

- **Отдельная таблица связей «многие ко многим»** — лишняя сложность: ни одному
  сценарию не нужно больше одного родителя.
- **Отдельные механизмы для эстафеты и тредов** — два кода с одинаковыми проверками
  доступа, риск разойтись.
- **Хранить связь на клиенте** — теряется между устройствами, а Дима работает с телефона
  и с мака.

## Последствия

- Миграция схемы таблицы сессий; откат требует удалить колонки и переделать сайдбар.
- Новый вид связи — новое значение колонки, но всегда с единственным родителем.
- Удаление родителя оставляет у детей висячую ссылку; сайдбар должен это переживать.
