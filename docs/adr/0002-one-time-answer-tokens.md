# 0002. Одноразовые токены ответа вместо HMAC; токен тратится после доставки

**Статус:** принято, 2026-10-12

## Контекст

Ответить на вопрос агента нужно из пуша и из Telegram, не открывая Neo3 (R17–R21).
Нажатие кнопки в service worker и `callback_query` Telegram приходят без обычной
авторизации. В `callback_data` Telegram помещается не больше 64 байт. Повторное нажатие
или нажатие после того, как вопрос сняли, не должно ничего делать (R21.1). Ответы из UI,
пуша и Telegram должны вести к одному и тому же результату для Claude и Grok.

## Решение

- Модуль `pending-answers` с единой операцией «ответить» поверх существующих путей:
  резолвер ожидания у Claude, продолжение Grok тем же путём, что ответ из UI.
- Для пуша и Telegram выдаются одноразовые токены, хранящиеся в таблице: случайные
  16 байт, привязаны к пользователю, запросу и конкретному варианту ответа, живут 24 часа.
- Токен сам по себе является правом: эндпоинт ответа по токену не требует авторизации.
- Токен считается потраченным только после того, как ответ доставлен в сессию; повторная
  попытка получает «уже отвечено». Ответ из любого канала гасит все токены этого запроса.

## Рассмотренные варианты

- **Подписанные HMAC-ссылки** — подпись вместе с идентификаторами не влезает в 64 байта
  Telegram, а одноразовость всё равно требует хранить факт использования.
- **Тратить токен в момент нажатия, до доставки** — сбой доставки сжигал бы кнопку,
  и ответить можно было бы только из Neo3.
- **Требовать вход в Neo3 для ответа** — ломает смысл «ответа без открытия».
- **Отдельные пути ответа для каждого канала** — расхождение поведения; выбран один вход.

## Последствия

- Утечка непотраченного токена в течение 24 часов позволяет дать ровно один заранее
  заданный ответ на один вопрос — граница риска осознанная.
- Таблица токенов растёт; просроченные записи нужно чистить.
- Отказ от токенов означает перепривязку кнопок пуша, Telegram-клавиатуры и эндпоинта.
