# 0019. Моды в чатах Grok — общий кадр `background_tasks` со `stoppable` от сервера и узкое разрешение записки переноса

**Статус:** принято, 2026-10-14

## Контекст

Пульт фона и «Перенести» должны работать в чатах Grok (R19), но Grok сам исполняет команды,
снаружи их не остановить, а записку переноса разрешено писать только Claude.

## Решение

- Фоновые команды Grok сворачиваются на сервере Grok-провайдера в тот же кадр
  `background_tasks`, что у Claude. Можно ли остановить задачу, решает сервер: флаг `stoppable`
  в кадре по наличию движка в `stopTaskFns`; клиент только читает и вместо «Стоп» пишет
  «остановить может только сам Grok».
- «Перенести» в чате Grok: записка разрешается узким правилом
  `--allow Edit(<проект>/docs/handoff/…)`. В фазах плана Grok (plan/planBypass без инструментов
  записи) ход переноса идёт обычным ходом. У Codex и Claude режим хода не меняется.

## Почему

- Отвергнуто: свой формат кадра и свой пульт для Grok — второй клиентский компонент на ту же
  задачу.
- Отвергнуто: клиент решает про «Стоп» по `provider` — список движков дублировался бы в UI и
  расходился с сервером при появлении остановки у нового движка.
- Отвергнуто: ход переноса в полном доступе у Grok — шире нужного; правило на одну папку
  `docs/handoff/` даёт ровно право записать записку.
- Отвергнуто: менять режим хода переноса у Codex — у Codex planBypass уже полный доступ, сузить
  его нельзя; у Claude записка и так разрешена.

## Последствия

- Формат событий Grok разбирается по образцам `~/.grok/sessions`; смена формата в новой версии
  CLI тихо опустошит пульт.
- В фазе плана ход переноса Grok выходит из плана — переходит в обычный режим на один ход.
- Правило `--allow Edit(...)` привязано к синтаксису флагов Grok CLI; его изменение сломает
  только перенос в Grok, и заметно это станет лишь по отсутствию записки.
- Новый движок со стопом нужно только зарегистрировать в `stopTaskFns` — клиент кнопку
  покажет сам; забыть регистрацию = кнопки нет без ошибки.
