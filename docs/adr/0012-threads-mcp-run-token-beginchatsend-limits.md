# 0012. Треды — MCP-сервер Neo3, токен на прогон в окружении движка, запуск через `beginChatSend`

**Статус:** принято, 2026-10-12

## Контекст

Агент должен сам открывать настоящие чаты и раздавать им задачи (R13–R17): по умолчанию
на Grok, чтобы не тратить лимит Claude. Инструменты нужны всем трём движкам. Дети
должны быть видны в сайдбаре, в них можно зайти и написать. Ребёнок наследует права
родителя и не больше (R24i), треды не должны бесконтрольно плодиться (R25i).

## Решение

- Отдельный stdio MCP-сервер `neo3-threads` по образцу browser-use, общий для Claude,
  Codex и Grok. Глобальная регистрация в настройках движков выполняется только при
  `NEO3_THREADS_MCP=on`; без флага сервер не регистрируется.
- MCP-сервер ходит в Neo3 по локальному HTTP-роуту тредов; авторизация — токеном треда,
  а не JWT пользователя.
- Токен выдаётся на прогон родителя, привязан к его сессии и пользователю, живёт до конца
  прогона плюс 24 часа и передаётся через окружение процесса движка. Если движок не
  пробрасывает переменную в MCP — инструмент честно отвечает «тред недоступен в этом
  движке».
- Тред запускается через `beginChatSend` с отдельным видом доступа «тред» и сокетом-
  заглушкой: прогон идёт через общий реестр, виден в UI, у него есть индикатор и «стоп».
- Лимиты: тред только в проекте родителя и от его пользователя; не больше 3 одновременно
  работающих тредов на родителя; тред не открывает свои треды. Claude-треды подчиняются
  защите лимита 5 часов. Связь с родителем — через `session-links` (ADR 0009).

## Рассмотренные варианты

- **Сабагенты движка** — в них не зайти и не поправить, другие движки недоступны.
- **`runHeadlessPrompt`** — идёт мимо реестра прогонов: нет статуса, «стопа» и такого
  чата в сайдбаре.
- **Встроенные инструменты отдельно в каждом движке** — три реализации вместо одной.
- **Идентичность через аргументы инструмента или JWT пользователя в окружении** —
  агент мог бы подставить чужую сессию; долгоживущий JWT шире нужного права.
- **Регистрация MCP всегда** — затрагивает глобальные настройки движков и терминальные
  сессии без явного решения.

## Последствия

- Без флага треды недоступны вовсе; включение пишет в глобальные конфиги движков, и
  терминальные сессии видят сервер (без токена он отказывает).
- Утечка токена в течение его жизни даёт право открыть треды в одном проекте от имени
  родителя, в пределах лимитов.
- Поведение зависит от проброса окружения в MCP у каждого движка; смена этого в новых
  версиях CLI тихо отключит треды в одном из движков.
- Отказ от `beginChatSend` или вида доступа «тред» потребует переделать индикатор, стоп
  и статус тредов.
