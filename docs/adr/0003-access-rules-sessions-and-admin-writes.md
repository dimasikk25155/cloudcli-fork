# 0003. Общее правило доступа к сессии; запись в вольт и .secrets.env только админом

**Статус:** принято, 2026-10-12

## Контекст

Neo3 мультиюзерный (R37i). Статусы, счётчики, хаб, ответы из пуша, Telegram и
WebSocket не должны открывать чужие сессии. До волны ответ через WebSocket не проверял
доступ к проекту сессии — это была дыра. Файлы `.secrets.env` и вольт Obsidian
принадлежат Диме и лежат на его машине; клиенты Neo3 писать туда не должны (R39i).

## Решение

- Одно правило: пользователь видит и отвечает только в сессиях проектов, к которым у
  него есть доступ. Его применяют список статусов, проверка «может ли ответить», выдача
  токенов (токен привязан к пользователю и запросу) и ответ через WebSocket.
- Отметка «просмотрено» хранится отдельно для каждого пользователя.
- Сохранение секрета в файл и запись заметки в вольт — только для админа. Не-админ
  получает в страже секретов только «Убрать из сообщения» (значение заменяется
  пометкой с именем), предложения заметок строятся только для сессий админа.
- Путь заметки строго внутри корня вольта; значение секрета не логируется и не
  возвращается в ответе API.

## Рассмотренные варианты

- **Проверки доступа в каждом канале по-своему** — расхождения и новые дыры.
- **Общий «просмотрено» на сессию** — действия одного пользователя гасили бы счётчик
  другому.
- **Отдельный файл секретов на пользователя** — требует модели хранения секретов
  клиентов, вне рамок волны.
- **Заодно закрыть фильтр у старого списка запущенных сессий** — отдельная задача
  безопасности, сознательно не трогаем.

## Последствия

- Старый список запущенных сессий остаётся без фильтра по пользователю до отдельной задачи.
- Любой новый канал ответа обязан идти через то же правило доступа.
- Клиентские установки не получают сохранения секретов и заметок, пока не появится своя
  модель хранения.
