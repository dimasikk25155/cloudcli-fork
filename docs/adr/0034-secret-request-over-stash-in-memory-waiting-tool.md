# 0034. Запрос ключа: ожидание в инструменте, запрос только в памяти, запись через secrets-stash

**Статус:** принято

## Контекст

Агенту нужен секрет (например, токен страницы), который Дима раньше вытаскивал руками. Значение не должно попадать в чат, лог, кадры и базу. Перенос ключа в файл секретов уже умеет `secrets-stash`.

## Решение

Инструмент `secret.request {name, why}` создаёт запись только в памяти сервера и ждёт ответа до 600 секунд. Дима вводит значение в скрытое поле в «Ждут тебя»; оно одним запросом идёт в `secrets-stash` и пишется в файл секретов. Агент получает только «NAME сохранён» или «Дима отказал». Существующее имя без явной галочки не перезаписывается. WS-кадр об изменении не несёт содержимого.

## Почему

Отвергнуто хранение запроса в БД: вместе с ним на диск попали бы текст «зачем» и состояние, а значение рядом с ними при ошибке реализации. Отвергнут ввод значения в чат с последующей маскировкой: страж секретов лишь блокирует вставку, но значение уже в истории движка. Отвергнута передача значения агенту в ответе: цель в том, чтобы он его никогда не видел. Отвергнут свой писатель в файл секретов: второй путь записи и второе место для ошибок с перезаписью.

## Последствия

Рестарт сервера теряет все ожидающие запросы, а висящий вызов агента завершается ошибкой. Запрос без ответа через 600 секунд агент получает как «спроси позже», а карточка остаётся. Пока Дима не ввёл ключ, агент занимает вызов инструмента. Ключ в файле секретов агент теоретически может прочитать обычными средствами, если ему открыт доступ к файлу: гарантия касается только самого запроса. Разрешено только имя по шаблону из заглавных букв.
