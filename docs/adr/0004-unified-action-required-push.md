# 0004. Пуш «нужен ответ» одним кодом для всех движков и снятие по tag

**Статус:** принято, 2026-10-12

## Контекст

Пуш «нужен ответ» был только у Claude (старый пуш о разрешении), у Grok и Codex его не
было (R15, R16). На один вопрос должен приходить один пуш (R16.1). Chrome на Android не
поддерживает Badging API, поэтому число на иконке TWA рисует лаунчер по активным
уведомлениям (R12). Android показывает не больше двух кнопок у уведомления.

## Решение

- Пуш отправляет `session-attention` при переходе сессии в «ждёт» — с единым кодом
  action-required и кнопками из выданных токенов. Старый пуш Claude о разрешении
  заменён этим. Дедуп по сессии и запросу.
- Codex блокирующих вопросов не даёт, для него «ждёт» определяет классификатор текста.
- Уведомление висит, пока на вопрос не ответили, и снимается по `tag`, когда ответ
  пришёл из любого канала. На десктопе и в iOS-PWA число ставит `setAppBadge`.
- Состав кнопок: один вопрос без мультивыбора — первые два варианта, тап по телу
  открывает сессию; несколько вопросов или мультивыбор — только «Открыть». План —
  «Одобрить / Открыть», разрешение — «Разрешить / Отклонить». В Telegram — все варианты
  (до 8) и «Открыть в Neo3».
- Service worker по нажатию отправляет токен без авторизации и показывает итог тихим
  уведомлением.

## Рассмотренные варианты

- **Пуш из каждого движка отдельно** — три копии логики и двойные пуши у Claude.
- **Число на иконке через Badging API везде** — на Android Chrome не работает.
- **Одноразовые пуши без снятия** — лаунчер показывал бы устаревшее число, а
  отвеченные вопросы висели бы в шторке.

## Последствия

- Число на иконке Android зависит от лаунчера и честно только при аккуратном снятии
  уведомлений по `tag` из всех каналов ответа.
- Старый код пуша Claude о разрешении больше не используется; возвращать его — значит
  получить двойные пуши.
- Варианты сверх двух видны только в тексте пуша или в Telegram.
