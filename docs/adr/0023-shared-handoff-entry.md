# 0023. Единая передача объекта в обычный чат проекта

**Статус:** принято

## Контекст

Письмо, документ, файл или поручение нужно передать агенту с контекстом источника. Для запуска уже существует обычный путь создания сессии и отправки сообщения. Новый отдельный runner мог бы обходить выбор проекта, модели, режима и штатный пользовательский контроль отправки.

## Решение

Использовать одну серверную точку разрешения handoff для поддерживаемых типов источника. Она возвращает контекст с проектом, источником и его версией; для доступа инструментов создаётся отдельный scoped grant. UI открывает обычный composer выбранного доступного проекта, заполняет черновик и продолжает штатный сценарий создания сессии и выбора модели/effort. Отправка остаётся явным действием пользователя. При переключении проекта секция workspace перемонтирует свою панель, чтобы локальное состояние и выбранный объект панели не сохранялись для другого проекта.

## Почему

Набор отдельных способов передачи со временем расходился бы в проверках доступа и поведении интерфейса. Собственный runner дублировал бы существующий send path и мог запускать обработку внешнего ввода автоматически. Общий resolver даёт одинаковый формат контекста, а обычный composer сохраняет единый контроль над запуском.

## Последствия

Переданный контекст — черновик, не команда на запуск. Сервер проверяет доступ к проекту и источнику, а инструментальный доступ дополнительно требует привязанного grant. Открытие composer, локальная сборка или успешный handoff не подтверждают обработку браузером, фактическую отправку письма или внешний E2E.
