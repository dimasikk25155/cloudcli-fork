# ADR: scoped workspace поверх существующего Neo3

Используем существующие Express, React, SQLite и run-token MCP, без новой зависимости или параллельного runner. Общая таблица хранит записи с владельцем, проектом и CAS revision. Feature-роутеры компонуются лениво после bootstrap окружения/БД; импорт runtime не открывает SQLite.

Handoff является действием пользователя. Сервер разрешает источник, сохраняет grant owner+project+source, затем однократно связывает grant с проверенной сессией. Передача текста через браузер не заменяет capability. Инструмент агента берёт проект из token→session; любые id проходят дополнительную проверку проекта. Доступ к письму требует отдельного bound grant и текущего владельца ящика. Generic произвольный router proxy не используется.

Человеческие approve/send/publish не включены в MCP dispatcher. Провайдерная отправка фиксирует approved snapshot и состояние до сети; неизвестный итог не ретраится. Это граница API-инструментов, а не песочница администратора: агент с полным shell-доступом к машине не ограничивается этим dispatcher и обязан соблюдать пользовательские правила.

Публичный intake — ограниченная детерминированная схема, без модели, shell и файлов; отдельные capabilities и лимиты. Текстовый поиск по opt-in документам предсказуем и не затрагивает личный Obsidian. Печать браузера вместо неподтверждённой генерации серверного PDF.

UI handoff проходит через штатный handleNewSession и composer submit, сохраняя политику provider/model/effort и пользовательский черновик. Не выполняется автоматическая отправка. Feature key projectId+section сбрасывает локальный контекст при смене проекта.
