# Общий выпуск Neo3 — 03.11.2026

Пользователь явно разрешил собрать работы четырёх сессий, применить весь выпуск и перезапустить Mac Neo3. Это новый выпуск: прежний coordinated-release уже завершился 03.11 в 12:03 МСК, но отдельная ветка рабочего пространства в него не входила.

## Исполнитель и границы

`scripts/apply-combined-local-release.mjs` применяет только заранее проверенные сборки из явного манифеста. Он не собирает код, не устанавливает зависимости, не меняет Git, конфигурацию запуска, секреты, почтовые настройки или содержимое БД. Перед применением SQLite online backup сохраняет WAL и проверяет `quick_check`; БД автоматически не восстанавливается.

Запускать только отдельной одноразовой задачей launchd, например через `launchctl submit`, с абсолютными путями к Node, скрипту и манифесту, отдельными stdout/stderr. Исполнитель проверяет, что его группа процессов отличается от группы Neo3. Запуск дочерним процессом текущего чата будет отклонён. Перезапуск Neo3 может оборвать сам чат; независимый исполнитель продолжит проверки и запишет `status.json` и читаемый `report.md` в папку манифеста. Старт задачи не означает успешного выпуска.

Старую завершённую задачу coordinated-release предварительно выгрузить, сохранив её журналы. Не запускать её повторно и не запускать второй исполнитель параллельно. Проверить свободное место, состояние рабочих сессий и актуальность ожидаемого PID перед запуском.

## Манифест

Новая приватная папка внутри `~/.cloudcli/maintenance/`; внутри неё `stage/dist` и `stage/dist-server`, без симлинков. `manifest.json` содержит:

```json
{
  "authorized": true,
  "service": "com.dimasik.neo3-local",
  "root": "/Users/dimasik/Antigravity Project/claude agent/cloudcli-fork",
  "expectedPid": 12345,
  "sourceSha": "<полный проверенный Git SHA>",
  "sourceHash": "<sourceHash(root)>",
  "hashes": {
    "live": { "dist": "<treeHash>", "dist-server": "<treeHash>" },
    "stage": { "dist": "<treeHash>", "dist-server": "<treeHash>" }
  },
  "stage": "<абсолютный путь новой папки>/stage",
  "database": "<путь действующей SQLite>",
  "origins": ["http://100.96.100.39:3005", "https://claude.neo3.ru"],
  "expiresAt": 0,
  "controller": { "pid": 12346, "sessionId": "<id текущей управляющей сессии>" }
}
```

Числа и заполнители выше — пример формата, не готовая команда. `expiresAt` — время Unix в миллисекундах, не дальше часа от запуска. `controller` необязателен; разрешает только указанный прямой дочерний Codex с совпадающим working session ID. Иные процессы и working-сессии ожидаются максимум 15 минут и до срока манифеста; done/waiting/failed из старой попытки не образуют вечный список блокировок. Несовпадение SHA, исходников, артефактов, PID, другого выпуска или личности управляющего процесса сразу запрещает применение.

Отпечатки вычислять экспортами `treeHash(path)` и `sourceHash(root)` из самого исполнителя после всех правок и проверок. Тестовые артефакты и документация не входят в sourceHash; исходники, scripts, public, основные конфиги и package/lock входят. Не изменять их между проверкой и применением. Полный SHA закрепляет Git-версию дополнительно.

Команда независимой задачи: `node /absolute/path/scripts/apply-combined-local-release.mjs --apply /absolute/path/manifest.json`. Одноразовость обеспечена наличием `status.json`, глобальным exclusive lock и записью намерения рестарта до команды. Не удалять статус/lock для слепого повтора; сначала разобрать результат и проверить процесс.

## Применение, проверка и откат

Перед заменой повторяются проверки исходников, артефактов и активности, затем сохраняется БД. Обе сборки перемещаются в `dist.before`/`dist-server.before`, проверенные становятся рабочими. Если работа возобновилась до рестарта — сборки возвращаются без рестарта. Далее записывается durable marker и выполняется один `launchctl kickstart -k`.

До двух минут проверяются новый PID, `/health` и `/` обоих адресов, точный SHA отданного JS, HTML публичной анкеты, отказ 401/403 внутреннего workspace без авторизации, отказ 404 публичной анкеты на заведомо неверный токен и наличие `workspace_records`, `run_durations`, `improvement_ideas`. Никаких настоящих писем, форм или заявок эти проверки не создают. Проверка внутреннего API подтверждает границу авторизации, не успешный пользовательский сценарий.

При неуспешной проверке старые сборки восстанавливаются, выполняется ровно один отдельно записанный восстановительный рестарт, затем проверяются старый JS, health и новый PID. Общий результат остаётся `failed`, даже если `rollback.status=verified`; неуспешный откат тоже явно записывается. БД с новыми аддитивными таблицами остаётся на месте, чтобы не потерять новые пользовательские данные.

Файлы результата: `status.json`, `report.md`, `auth.before.db`, сохранённые сборки; доступ владельцу. Код выхода 0 означает только `status=verified`, остальные результаты — 1. Доставка почты, PDF через печать браузера и полный браузерный сценарий не подтверждаются этим исполнителем.

Проверки реализации: `node --test scripts/apply-combined-local-release.test.mjs`; тесты на подставленных эффектах, никаких production launchctl/DB/network действий.
