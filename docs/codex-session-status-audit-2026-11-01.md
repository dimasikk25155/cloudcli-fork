## Причина ложного красного таймера

`server/openai-codex.js` передаёт начало и завершение SDK-инструмента с
одним id. `CodexSessionsProvider.normalizeMessage()` для MCP и команд
возвращает `kind:tool_use` как при `in_progress`, так и при `completed`.

`src/components/chat/hooks/useChatRealtimeHandlers.ts:412` открывает шаг
на каждом `tool_use`, не проверяя терминальный `status`; закрывает только
на `tool_result` (строка 431). `OpenSteps.start()` сохраняет первое время
данного id, а `current()` возвращает самый старый незакрытый шаг.
В результате выполненный первый вызов остаётся текущим до конца хода.
Порог 5 минут из `stepTimer.ts` красит этот ложный шаг как затянувшийся.

Воспроизведено без запуска модели: использован адаптер из текущего
`dist-server` и настоящий `OpenSteps`, с временными HOME и DATABASE_PATH.

```text
SDK in_progress -> kind tool_use, status in_progress -> open js
SDK completed   -> kind tool_use, status completed   -> still open js
at 31m45s       -> same open step, isStepOverdue = true
```

## Почему не переключается на размышление

В `normalizeMessage()` проверка `raw.message?.role` (строка 458) идёт
раньше обработки `raw.type === 'item'`. Преобразованное SDK-событие
`reasoning` содержит `message.role:assistant` и попадает в обработчик
истории: получается `kind:text` вместо `kind:thinking`.
На текущей серверной сборке воспроизведено:

```text
itemType reasoning + message.role assistant -> text (expected thinking)
```

Следовательно, ветка клиента `case 'thinking'` не получает нужное событие.
Само исправление таймера не устранит эту отдельную причину неверной фазы.

## Объём необходимого исправления

1. Согласовать жизненный цикл Codex-инструментов с клиентом: терминальные
   статусы закрывают соответствующий шаг; обновления не запускают его заново.
   Учесть failed, поиск и todo, завершение которых сейчас теряет часть
   информации при преобразовании SDK-события. Сохранить одну строку истории
   на вызов и уникальность id между ходами.
2. Обрабатывать живые SDK `item` до общего fallback истории, сохраняя
   `reasoning` как фазу thinking, без вывода внутренних рассуждений в текст.
3. Проверить переходы thinking → tool → thinking, ошибку инструмента,
   параллельные вызовы и окончание хода. Нужен тест закрытия таймера:
   существующий тест `Codex tool progress updates one row per turn…`
   проверяет обновление строки, но не потребителя её статуса.
