# Длительность завершённого ответа

Реализовано в исходниках 02.11.2026 по запросу Димы: строка под финальным
ответом «Выполнено за 2 мин 15 сек», как в Codex. Отдельного выпуска из этой
сессии не было; применение — вместе с согласованным общим выпуском
(`coordinated-release-2026-11-02.md`).

## Поведение

- Реестр запусков измеряет время от начала запуска до успешного `complete`
  монотонными часами. Время инструментов и ожидания ответа пользователя входит
  в общую длительность. Ошибки, отмена и запуск без текста ответа не помечаются.
- Таблица `run_durations` хранит длительность, границы запуска и SHA-256 ответа,
  без копии текста. Создаётся штатной инициализацией БД, запись удаляется вместе
  с сессией. Дубликат завершения не создаёт второй замер.
- После штатного обновления истории подпись появляется под финальным ответом;
  сохраняется после перезагрузки браузера и перезапуска сервера. Обогащение
  истории выполняется до разбивки на страницы, доступ остаётся за существующим
  защищённым маршрутом истории.
- Старые ответы без замера не получают выдуманную длительность.
- У Grok время истории приблизительное: используется только однозначный
  отпечаток ответа. Повторяющиеся идентичные ответы Grok остаются без подписи.
- Длительность — элемент интерфейса; в копируемый текст ответа не добавляется.

## Проверено

- 21 целевой тест: сохранение и повторное чтение БД, успех/ошибка/отмена,
  повторный `complete`, дочерние агенты, история и её страницы, одинаковые
  ответы разных запусков, формат секунд/минут/часов, нормализация клиента.
- `npm run typecheck` и ESLint изменённой логики.
- Изолированная клиентская сборка Vite, без записи в рабочий `dist/`.
  В сборке остаются предупреждения существующего CSS и размеров пакетов.

подпись под ним и сохранение подписи после обновления страницы. Боевой ответ
из браузера в рамках этой задачи не проверялся.
