# Тема Codex и режимы работы

## Изменения

- Добавлена отдельная тема `codex`: графитовый фон `#181818`, сайдбар `#242424`, панели `#2c2c2c`, нейтральные границы и светлый текст.
- Шрифт — системный macOS с запасными Segoe UI/sans-serif; сообщения — 14 px, межстрочный интервал 1,65.
- Сайдбар на десктопе — 260 px; сообщения и поле ввода ограничены шириной 48 rem.
- Поле ввода получило скругление 18 px, компактные переключатели и круглую кнопку отправки; на мобильном textarea использует 16 px.
- В чате при ширине от 1280 px показана правая панель «Среда»: изменения Git, файлы проекта, статистика. При открытом редакторе она скрыта.
- Существующие иконки проектов и провайдеров сохранены. Оформление ограничено темой Codex.

## Режимы

- Для Codex открыты планирование, планирование с выполнением, брифы, уточнения и автопилот сборки.
- Инструкции текущего режима передаются через SDK `config.developer_instructions`, отдельно от текста пользовательского сообщения.
- Планирование использует sandbox `read-only`, запрещает реализацию и заканчивается конкретным планом.
- Уточнения также используют `read-only`: агент задаёт пакет из 2–4 вопросов и останавливается до ответа.
- Composer сбрасывает одноразовый режим после отправки; следующий ответ пользователя может продолжить согласованную работу с правами выполнения.
- Codex «план + выполнение» сначала публикует план и затем реализует его; при выбранных уточнениях ждёт ответов.
- Семантика Claude сохранена. Существующий Grok «план + выполнение» по-прежнему начинает с вопросов; размер пакета уточнений — 2–4. Полной идентичности этого режима между провайдерами нет.
- Брифы описывают этапы работы без обязательного подтверждения перехода к каждому следующему этапу.

## Проверено

- Пройдены 74 целевых теста и проверки типов клиента и сервера.
- Vite-сборка создана в `/tmp/neo3-codex-preview`, сервер скомпилирован в `/tmp/neo3-codex-server`.
- Один живой SDK smoke-тест с `gpt-5.6-luna`: агент задал четыре вопроса и остановился.
- Клиент установлен в `dist`; резервная копия прежней точки входа — `/tmp/neo3-before-codex/index.html`.
- Тема выбрана только для владельца `user_id=1`; принадлежность подтверждена аудитом текущей сессии.
- Локальный HTTP вернул 200, точка входа соответствует установленной сборке.

## Активация и ограничения проверки

- Пять скомпилированных серверных модулей подготовлены к применению.
- Одноразовый launchd `com.dimasik.neo3-codex-apply-once` ожидает завершения активного прогона.
- Источник фактического статуса активации — `/tmp/neo3-codex-apply-status.json`; подготовка файлов сама по себе не подтверждает обновление работающего сервера.
- Проверка публичного HTTPS через CLI завершилась тайм-аутом; доступность публичного адреса не подтверждена.
- Пользователь одновременно работал в Firefox, поэтому проверка скриншотов не выполнена.
- Визуальное соответствие на десктопе и мобильном остаётся непроверенным. Заявлять полное совпадение с референсом нельзя.
- Следующий шаг: после активации проверить статус, публичный HTTP и скриншоты на десктопе и мобильном, включая заголовок на ширинах 768–1100 px.
