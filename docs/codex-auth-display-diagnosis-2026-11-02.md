## Установленная причина смены статуса

Codex CLI **0.166.0** перед `login --device-auth` вызывает
`clear_existing_auth_before_login`, а тот — `logout_with_revoke`.
Это происходит **до получения нового кода**, а не после успешного входа.
Ошибка или тайм-аут новой попытки не восстанавливают прежнюю авторизацию.

Первичный источник соответствующей установленной версии:
[cli/src/login.rs, строки 127–143 и 371–408](https://github.com/openai/codex/blob/rust-v0.166.0/codex-rs/cli/src/login.rs#L371).
В том же файле upstream-тест `clears_existing_auth_before_login` проверяет
исчезновение старой записи. Выдача/ожидание/сохранение нового входа:
[device_code_auth.rs](https://github.com/openai/codex/blob/rust-v0.166.0/codex-rs/login/src/device_code_auth.rs).

Поведение воспроизведено **установленными бинарниками Mac и VPS**, а не только
прочитано в исходниках: отдельные временные HOME/CODEX_HOME, фиктивный API key,
`cli_auth_credentials_store="file"`, `--no-daemon`, экспериментальный issuer
`http://127.0.0.1:1`. Оба запуска завершились exit 1 на соединении с локальным
адресом, фиктивный `auth.json` исчез. Реальных токенов и запросов кодов не было.
Эта проверка доказывает удаление локального входа; успешность отзыва настоящего
токена на стороне OpenAI не проверялась.

## Проверка отображения

Добавлен `scripts/codex-display.test.mjs`: два последовательных хода одной
сессии с разными безопасными маркерами, но одинаковым нативным `item_0`.
Контролируемый SDK-поток проходит через настоящий `queryCodex`, реестр прогонов,
переназначение sessionId, буфер повторной доставки, функции слияния/очистки
хранилища и `normalizedToChatMessages` (подготовка пузырей чата).

Проверено: разные id ответов, правильная сессия, один complete на ход,
отсутствие позднего ответа от завершённого writer, повторная доставка после
переподключения и загрузка сохранённой истории без дублей/подмены.
Тест использует правила очистки live-строк из настоящего store; без этого шага
искусственный сценарий давал дубль и не соответствовал работе приложения.

Целевой набор: **54/54** — новый тест, openai-codex, codex-auth,
chat-run-registry, sessionMessageMerge, useChatMessages. HOME/БД временные,
наследуемый CODEX_HOME сброшен. Лог: `/tmp/neo3-auth-display-tests.log`.
`npm run typecheck` и `git diff --check` прошли. После добавления защиты теста
от запуска с рабочим HOME новый интеграционный тест повторно прошёл отдельно.

Тест лежит в `scripts/`, поскольку связывает серверный и клиентский код с разными
правилами TypeScript. Он не входит в обычный `npm test`; запуск вместе с полным
набором через изолирующий runner: `npm test -- scripts/codex-display.test.mjs`.

Это интеграционный тест кода с контролируемым SDK, не браузерный end-to-end
и не реальный ответ модели VPS. В этих проверенных сценариях подмена не
воспроизведена; отсутствие всех возможных ошибок интерфейса не заявляется.

## Следующий шаг требует присутствия владельца

Сначала получить готовность пользователя завершить один вход. Затем одна новая
постоянная панель Herdr, один login-процесс от `agents`, свежий вывод этой панели,
время выдачи и истечения кода; никакого параллельного login/logout. Проверить
завершение именно этого процесса, затем login status и отдельный контрольный
запрос модели. При браузерном отказе сохранить только безопасную ошибку и время,
не объяснять её старым успешным статусом и не выпускать новые коды автоматически.

[Официальная инструкция](https://learn.chatgpt.com/docs/auth) требует разрешённого
device-code login в настройках аккаунта/рабочего пространства. Его состояние
у владельца не проверено. Если один согласованный device flow снова не работает,
рассмотреть документированный браузерный вход с SSH-туннелем; не копировать auth
с Mac и не менять настройки безопасности аккаунта без решения владельца.

Отдельное согласование выкатки Neo3 и переключения Крабика по handoff сохраняется.
Совместимость модов и оставшиеся ограничения — в
`codex-compatibility-audit-2026-11-02.md` и `codex-mods-parity-2026-11-01.md`.
