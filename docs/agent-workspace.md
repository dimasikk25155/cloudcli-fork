# Рабочее пространство агента

Раздел открывается из меню Neo3: Мой день, Почта, Документы, Знания, Команда, Заявки. Проект выбирается явно. При переключении проекта feature-панель пересоздаётся; несохранённые поля другого проекта больше не активны.

## Подключение и границы

Нужны существующая SQLite приложения (`DATABASE_PATH`) и проект с назначенными пользователями. Для AgentMail задаются `AGENTMAIL_API_KEY`, `AGENTMAIL_INBOX_ID`, `AGENTMAIL_OWNER_USER_ID` в защищённом окружении сервера; значения в чат не вставлять. Если владелец не указан, автоматический выбор возможен только при единственном администраторе. Без настройки UI показывает «Почта не подключена». Настройка или наличие ключа не доказывает доставку.

Почта принадлежит одному владельцу. Синхронизация не запускает агента. Письма отображаются как текст. Отправка требует явного утверждения текущего снимка; редактирование отменяет согласие. `accepted` означает принятие API, не доставку адресату. `sending`/`uncertain` после сбоя не повторяются автоматически: сначала выяснить результат у провайдера.

Документы содержат неизменяемые версии; шаблон сначала утверждается человеком. Согласование последовательно и связано с версией, изменения отменяют цепочку. Знания ищутся только по документам, явно включённым владельцем. «Сохранить PDF» вызывает печать браузера; пользователь выбирает PDF.

Публичная страница `/neo3-intake.html#<form-token>` копируется Vite из `public/`; API `/api/public-intake` использует отдельные form/session capabilities, не staff JWT. Новые формы выключены. Только сотрудник включает ссылку и назначает исполнителя. Посетителю недоступны агент, файлы и внутренние записи. Не публикуйте URL формы до согласования; токен сессии посетителя нельзя передавать другому человеку.

## Передача и MCP

«Передать агенту» сохраняет серверную capability конкретного источника, открывает штатный новый чат выбранного проекта и добавляет материал к существующему черновику. Движок/модель/effort выбираются штатной политикой нового чата. Автоотправки нет. Перед первой отправкой capability одноразово связывается с настоящим sessionId; непривязанная передача истекает через 10 минут. Браузерный sessionStorage — только черновик, не право доступа.

`neo3-threads` предоставляет инструмент `workspace_action` через уже существующую MCP-регистрацию Claude/Codex/Grok. Сервер проверяет run token, актуальную сессию/проект/пользователя при каждом вызове. Допустимы `document.list/read/create/revise`, `knowledge.search`, `assignment.list/read/create/update`, `project.users`, `task.create`, `mail.read/draft`. В `data` передаются поля операции, `id`/`revision` указывают запись. Проект из аргументов игнорируется: берётся из сессии. Почта требует capability именно этого письма и чата плюс текущие права владельца. Агентный API не предоставляет approve/send/publish/sync и общий список ящика.

Когда мод тредов выключен, bound workspace handoff позволяет выдать run token; spawn/message остаются выключены. Без токена инструмент возвращает явную ошибку. Для доступа нужны существующие MCP-регистрации (`NEO3_THREADS_MCP=on` при согласованном запуске сервера); уже работающие прогоны новые инструменты не получают. У Grok тиммейтов MCP недоступен по текущим ограничениям песочницы: используйте Claude/Codex для workspace tools. Сам текст handoff можно обрабатывать в обычном чате любого движка, наличие инструмента не изображается.

## Восстановление и выпуск

Данные находятся в `workspace_records` общей SQLite; миграция идемпотентна. Перед согласованной выкаткой сохранить согласованный Git SHA, конфигурацию LaunchAgent и консистентную резервную копию БД через SQLite backup API (не просто копировать открытый файл без WAL). Хранить копию с ограниченным доступом: в ней почта и capabilities. Проверить восстановление в отдельном временном `DATABASE_PATH` и отдельном HOME. Не запускать проверки на рабочей БД.

Выкатка требует отдельного разрешения: собрать из выбранного SHA, сохранить предыдущие dist/dist-server, применить миграцию, перезапустить и проверить authenticated staff API, публичную страницу с `text/html`, выключенную форму, новый MCP-прогон и пользовательский сценарий. При откате вернуть прежние сборки/конфигурацию; таблицу workspace_records не удалять. Восстановление всей БД из backup откатывает также другие изменения после снимка и требует отдельного решения.

Проверки разработки: `npm run typecheck`; `TMPDIR="$(node -p 'require("node:fs").realpathSync(require("node:os").tmpdir())')" npm test`; isolated Vite `--outDir` в `/tmp`; ESLint затронутых путей. Тестовый wrapper изолирует HOME и DATABASE_PATH. Полный glob включает тесты новых feature-модулей; интеграционный тест использует только fake provider.

В этой реализации не доказаны доставка реального письма/receipt, реальный внешний публичный посетитель, browser E2E переключения проектов и сохранения PDF. Production runtime, секреты и MCP-конфиги не изменялись.
