# Codex: моды Neo3 и серверный Крабик — 01.11.2026

## Что уже работает и чем это подтверждено

- Дуэт в текущей серверной сборке умеет выбирать Claude/Codex: `duetProvider()`
  учитывает `NEO3_DUET_PROVIDER`, затем настройку владельца; при отсутствии выбора
  Claude использует Codex. Анализ Codex изолирован: ограниченный снимок исходников,
  без инструментов, MCP, пользовательских хуков и секретов. Живой вызов
  `runCodexReadOnly` ответил `NEO3_DUET_CODEX_OK`. Это проверка анализатора,
  а не всего утреннего брифа или доставки уведомлений.
- Переносы чатов сохраняют движок, модель и effort. Для Codex уже есть отдельный
  регрессионный тест режима plan+auto-run. Реальную текущую беседу не переносили.
- Треды, отображение внутренних помощников Codex, «Ждут тебя», чипы, страж
  секретов, заметки, статус кода и работа со скриншотами имеют общие механизмы
  Neo3 или адаптеры Codex. Сводка предыдущей проверки плагинов:
  `docs/codex-compatibility-test-2026-10-31.md`.

## Что изменено в этой задаче

1. Крабик понимает нативную JSONL-историю Codex: сообщения, команды, apply_patch,
   вопросы и вызовы помощников. Дубли event/response склеиваются; системный
   контекст, внутренние рассуждения и сырые ответы инструментов не выводятся.
2. Серверный читатель истории привязывает файл к **текущему id и папке Крабика**,
   а не к последней сессии Codex на всём сервере. История Claude сохраняется.
3. Herdr сообщает фактический движок в `state.provider`. Обход с дополнительным
   Enter остаётся только для Claude: Codex не получает лишнюю клавишу.
4. Общий маркер `NEO3_SESSION=1` теперь получает и Codex из Neo3: общие хуки
   могут отличить его от независимого запуска CLI.
5. Подготовлен runtime для выбора Claude/Codex, проверки входа, восстановления
   после перезагрузки и отката. Он отказывает в переключении занятого агента,
   проверяет авторизацию **до** остановки прежнего движка и сохраняет выбор
   только после успешного запуска. Расписание 08:30 МСК не меняется.
   Для интерактивного Codex используется `--no-daemon`: общий background server
   отвергает отключённый code_mode_host и отделяет процесс от ожидаемого Herdr
   окружения. Состояние Herdr `done` нормализуется в «свободен», а не «спит».
6. Из подписи панели убрано историческое `NL`. На 01.11 IPinfo сообщает `FI`
   для IP сервера; `vps-nl` остаётся именем SSH-подключения, не доказательством
   физической страны дата-центра. Новый VPN или сервер не покупались.

## Установлено на VPS, без переключения движка

- `/usr/local/lib/neo3-krabik/runtime.py` — lifecycle/read-only transcript helper.
- `/usr/local/bin/krabik-ensure`, `/usr/local/bin/krabik-transcript` — обёртки.
- `/usr/local/lib/neo3-krabik/legacy-ensure` — исходный ensure для отката.
- `/home/agents/krabik/AGENTS.md` — Codex читает прежние серверные правила
  из CLAUDE.md; старое запрещение Codex отменено решением владельца.
- Выбор движка: `/home/agents/.config/krabik/provider`, отсутствует → Claude.

Повторная установка из папки `scripts/krabik/` на сервере: `sh install.sh`.
Она сохраняет выбор, действующую сессию, таймеры и существующий AGENTS.md.
Реальный установленный `krabik-ensure` вернул `ok`; reader прочитал историю
нынешнего Claude-агента. Содержимое истории в отчёт/терминал не выводилось.

## Применение после входа и отдельной выкатки Neo3

Сначала выпустить изменения панели и сервера Neo3, затем менять движок Крабика:
старая серверная сборка читает только Claude-историю и не должна обслуживать
уже переключённого Крабика. В рабочем дереве есть изменения других задач;
не включать их в выпуск автоматически. `dist/`, `dist-server/` и работающий
Mac LaunchAgent в этой задаче не пересобирались и не перезапускались.

```sh
ssh vps-nl 'sudo -u agents -H /usr/local/lib/neo3-krabik/runtime.py check codex'
ssh vps-nl 'sudo -u agents -H /usr/local/lib/neo3-krabik/runtime.py switch codex'
ssh vps-nl 'sudo -u agents -H /usr/local/bin/krabik-ensure'
```

Откат движка в свободной сессии: та же команда `switch claude`. Для отката самого
helper восстановить `legacy-ensure` в `/usr/local/bin/krabik-ensure`; истории,
отчёты и авторизацию не удалять. Автоматические права сохраняют уже согласованные
права старого Крабика; это не новая выдача sudo или расширение доступа.

Серверный вход выполнять в постоянной панели Herdr командой
`/usr/local/bin/codex login --device-auth`. Подтверждение в браузере завершено,
только когда `codex login status` от **agents** возвращает успех. Вход через
временный SSH-процесс может прерваться до сохранения авторизации. Коды и токены
в документацию не записывать, авторизацию Mac на сервер не копировать.

## Ограничения, которые нельзя объявлять полной совместимостью

- Claude-плагины с собственным SDK/TUI не становятся плагинами Codex от копирования
  папки. Общие навыки/MCP и хуки уже имеют отдельный слой совместимости; различия
  перечислены в `~/.codex/claude-parity/manifest.json`.
- Интерактивные кнопки разрешений/AskUserQuestion в push/Telegram имеют адаптеры
  Claude/Grok. Для нативного Codex такого адаптера пока нет; обычный ответ в чате
  и уведомление «Открыть» остаются доступны.
- Индивидуальная остановка фоновой команды Codex и Claude-мод `neo3-guards`
  не подключены как нативные адаптеры Codex. Кнопку без работающего механизма
  остановки не добавляли.
- Таймер кэша подписки Claude к Codex неприменим. Его отсутствие не означает
  поломку остальных модов.
