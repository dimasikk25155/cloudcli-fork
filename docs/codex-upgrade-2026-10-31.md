# Codex и моды Neo3: обновление 31.10.2026

## Реализовано

- Встроенные `@openai/codex-sdk` и CLI зафиксированы в lockfile на 0.166.0,
  совпадающей с опубликованной npm latest на момент проверки.
- Дуэт выбирает Codex либо Claude по настройке владельца; явный выбор —
  `NEO3_DUET_PROVIDER=codex|claude`. Лимит Claude больше не блокирует Codex.
- Брифы и идеи Codex получают ограниченный снимок до 20 исходников.
  Скрытые папки, `.env`, ключевые файлы, симлинки, зависимости и большие файлы
  пропускаются; обнаруженные ключи маскируются. Отдельный временный HOME,
  отключённые shell/MCP/apps/plugins/hooks/browser и sandbox read-only.
  Временная сессия и ссылка на локальный OAuth удаляются по завершении.
- Нативные помощники Codex показываются крабиками, включая восстановление
  состояния после чтения истории. Завершение spawn не завершает помощника:
  нужен его собственный completed/error. Повторные события не дублируют карточку.
- Прогресс команд и MCP Codex отображается во время выполнения. Идентификаторы
  строк стабильны внутри хода и различаются между ходами.
- Фоновые прогоны Codex учитывают токены, отдельно свежий вход и кэш; ошибка
  движка больше не записывается как успешная работа Дуэта.
- Пользовательские навыки Claude можно подключить к Codex через
  `node scripts/sync-codex-skills.mjs`. Источники остаются на месте; существующие
  каталоги не перезаписываются. Это подключение навыков, а не конвертер хуков.
- `scripts/upgrade-neo3.sh` обновляет Linux-инстанс из публичной ветки Neo3:
  отдельная сборка, typecheck, тесты, SQLite backup, сохранение старого кода,
  проверка нового бандла и автоматический откат. `self-update.sh` вызывает его.

## Совместимость встроенных модов

| Мод | Codex |
| --- | --- |

| Подсказки ответов, страж ключей | Общий клиентский/серверный механизм |

| Пометки на скриншоте | Общий интерфейс и структурированные изображения Codex |

## Границы проверки

Полный прогон: 1520 тестов, без ошибок. После дополнительных исправлений
пройдены целевые тесты Codex, Дуэта, истории, крабиков и учёта токенов.
Отдельно проверены успешное обновление, сбой загрузки, откат при нездоровом
сервисе и идемпотентное подключение навыков. Живой SDK smoke с GPT-6.1 Sol
вернул точный маркер из безопасного снимка исходников. Дополнительно
проверен полный скомпилированный путь runHeadlessPrompt с actor=duet:
ответ NEO3_HEADLESS_CODEX_OK, audit run.finish, вход 1757 и выход 12 токенов.

Сборка проверена из чистого checkout с SDK 0.166.0. В основной рабочей папке
есть отдельные незавершённые изменения, в том числе удалённые файлы Claude
provider. Они не входят в этот релиз и не восстанавливаются автоматически.

Крабик отвечал через `herdr agent get`: idle, готов к вводу. Новых задач ему
не отправлялось. Факт ответа не доказывает выполнение им задачи на Codex.

IGEN в исходниках, реестре 14 модов и установленных UI-плагинах по этому имени
не найден. До уточнения идентификатора нельзя утверждать его перенос.
Произвольные Claude-плагины с собственными хуками не становятся плагинами
Codex автоматически: требуется отдельная адаптация их событий.

Реальный запуск обновлятора на машине Мити не выполнен: доступ к ней не
предоставлен. Обновлятор использует только аккаунты и настройки этой машины,
не переносит секреты, SSH-доступ или авторизацию Димы. Для Крабика Мити нужны
собственный Herdr/SSH и собственный реестр сервисов Дуэта.

## Проверка и обновление

Команда для существующего Linux VPS — в [INSTALL.md](../INSTALL.md), шаг 3.
После установки: `/health` должен вернуть status=ok, фронтовый бандл должен
совпадать с `dist/index.html`, Codex авторизован своим аккаунтом ChatGPT.
Локальная подготовка сборки и работающий публичный backend — разные состояния:
новый серверный код начинает работать после перезапуска службы.

Upstream CloudCLI: через GitHub API проверен свежий v1.37.7 от 31.10.2026.
Его изменения интерфейса не смешивались автоматически с форком: проектный
CLAUDE.md требует отдельного выбора изменений и SHA перед переносом.
Встроенный Node-checker завершился fetch failed; результат GitHub API
проверен отдельно через curl. Это не успешное выполнение самого checker.

ESLint изменённых файлов не добавил ошибок. В agent-run.service.js остаются
7 прежних boundaries/no-unknown: такое же количество подтверждено lintText
на исходном HEAD. Они не объявляются прошедшей общей lint-проверкой.
